## 1. 切屏后无法唤出键盘 (P1)

**现象**: 发消息后切换到其它 app，再切回来，输入框无法唤出键盘，点击无效。

**排查**:

- `InputBar` 的 TextField 有 `.disabled(isStreaming)`
- 切屏回来时，SSE 连接可能尚未超时（Pro 180s / Flash 120s）
- `isStreaming` 仍为 `true`，TextField 处于 disabled 状态
- 直到后端超时回调 `finishStreaming()` → `isStreaming = false` 才能恢复

**修复方向**: 切回前台时主动检测 SSE 连接状态，若已断开则立即结束 streaming 状态。或监听 `scenePhase` 回到 `active` 时判断。

## 2. 消息发出后乱序 (P1)

**现象**: 消息显示顺序错乱，偶现。

**排查**:

- `ChatViewModel.updateLastAssistantMessage` 使用 remove+append 模式更新流式消息：
  ```
  messages.removeLast()  // count: N → N-1
  last = new Message(...)  
  messages.append(last)  // count: N-1 → N
  ```
- 在这个极短的 N→N-1 窗口内，SwiftUI 的 `@Published` 合并通知可能让 UI 看到"少了一条消息"的状态
- `SSEClient.processLines()` 在 URLSession delegate 线程解析，通过 `Task { @MainActor }` 派发到主线程。极端网络抖动下事件到达顺序可能不完全稳定

**修复方向**: 改用 in-place 更新 `messages[messages.count-1].content = content` 替代 remove+append。

## 3. 错误提示信息不友好 (P3)

**现象**: 删除记忆失败或其它操作报错时，提示信息直接展示系统错误原文（如 "The network connection was lost"），用户难以理解。

**方向**: 未来集中治理，统一把系统错误映射为用户友好的中文提示。
