# B5 评测引擎设计方案（草案）

> 2026-06-16 更新 · 离线试题集 Phase B5
>
> 习题集冻死后，评测引擎是独立消费者。核心设计：**SearchEngine 可插拔 + YAML 配置驱动**，不同搜索策略组合不改一行代码。
>
> **2026-06-16 更新**：移除 `QueryProcessor` 和 `CorpusProcessor`。query 文本和 corpus 形态在 B1 `ExportStrategy` 创建 project 时已定，评测引擎只管「怎么搜」。

---

## 一、设计目标

| 目标 | 说明 |
|------|------|
| **配置驱动** | 比较 N 种搜索策略 = N 条 YAML config，不改代码 |
| **可扩展** | 加新搜索方式只需实现 `SearchEngine` 接口 |
| **可追溯** | 评测配置和报告可存可 diff |
| **零负担** | 不修改冻死习题集，不加工 query/corpus |

## 二、核心抽象：SearchEngine

评测引擎只做一件事：读 eval.db 里的 query → 调 SearchEngine 搜 → 对比 ground_truth → 出报告。

```
eval.db（冻死）
  ├── raw_queries（query 文本，ExportStrategy 产出）
  ├── eval_corpus（语料 parent 级）
  ├── eval_corpus_chunks（子语料，可选）
  ├── eval_embedding_cache（向量，B1 预灌）
  └── eval_ground_truth（标注结果）
        │
        ▼
  SearchEngine (vector / keyword / hybrid)
        │
        ▼
  TopK Results → 对比 ground_truth → Recall / NDCG / MRR
```

### 2.1 SearchEngine 接口

```go
type SearchEngine interface {
    Name() string
    Index(ctx context.Context, db *sql.DB) error               // 从 eval_corpus [+ eval_corpus_chunks] 建索引
    Search(ctx context.Context, db *sql.DB, query string, topK int) ([]SearchResult, error)
}

type SearchResult struct {
    CorpusID string
    Score    float64
}
```

| 实现 | 索引 | 搜索 | 依赖 |
|------|------|------|------|
| `VectorEngine` | 读 `eval_embedding_cache` 中 corpus/chunk 向量 → 内存 | query 向量 → cosine | embedding API（仅 cache miss 时） |
| `KeywordEngine` | eval_corpus 文本 → SQLite FTS5 | FTS5 MATCH | SQLite 内置 |
| `HybridEngineRRF` | 包 vector + keyword | Reciprocal Rank Fusion 合并 | VectorEngine + KeywordEngine |

### 2.2 chunk 模式行为

当 project 的 `eval_corpus_chunks` 非空时，`VectorEngine` 的 `Index` 行为：

```
Index:
  读取 eval_corpus_chunks（子语料）
  读取 eval_embedding_cache（source_type='corpus_chunk', source_id=chunk.id）
  构建内存向量索引（key = chunk.id）

Search:
  query 向量 vs 所有 chunk 向量 → cosine → 排序
  按 eval_corpus_chunks.corpus_id 去重（取最高分 chunk）
  返回 parent corpus ID 列表（eval_corpus.id）
```

> `KeywordEngine` 和 `HybridEngine` 同理：索引建在 chunk 文本上，搜索结果按 parent 去重。

full-content 模式（无 chunk）：直接搜 `eval_corpus` 的向量/文本，不去重。

## 三、评测配置（YAML）

query 文本和 corpus 形态在 project 创建时已定，YAML 只管搜索方式：

```yaml
# searches.yaml — 一次跑多个搜索策略
evaluations:
  - name: vector_baseline
    engine:
      type: vector
      model: doubao-embedding-vision-251215
    top_k: 10

  - name: keyword_only
    engine:
      type: keyword
    top_k: 10

  - name: hybrid_rrf
    engine:
      type: hybrid_rrf
      vector:
        model: doubao-embedding-vision-251215
      fusion_k: 60
    top_k: 10
```

> 对比不同 query/corpus 形态？各有各的 project，分别跑上面这份配置，对比两个 project 的同名策略报告。

## 四、评测执行流程

```
加载 eval.db + YAML config
    │
    ▼
for each evaluation in configs:
    │
    ├── SearchEngine.Index(db)   ← 建索引（向量/关键词）
    │
    ├── for each query in raw_queries:
    │   ├── SearchEngine.Search(db, query.content, topK)
    │   └── 对比 ground_truth → 记入 PerQuery 结果
    │
    └── 汇总指标 → 写入 Report

输出对比报告
```

## 五、评测报告

### 单条 query 粒度的结果

```go
type QueryEvalResult struct {
    QueryID    string
    Query      string
    Retrieved  []SearchResult       // 检索返回的 top K
    GTRelevant []string             // ground_truth 中 relevance ≥ 3 的 corpus ID
    Metrics    struct {
        ReciprocalRank float64      // 第一个相关结果的排名倒数
        NDCGAt5        float64
        RelevanceAt5   []int        // top 5 的实际相关度
    }
}
```

### 汇总指标

```go
type MetricsSummary struct {
    RecallAt5     float64
    RecallAt10    float64
    PrecisionAt5  float64
    PrecisionAt10 float64
    NDCGAt5       float64
    NDCGAt10      float64
    MRR           float64
}
```

## 六、嵌入成本

- query 向量：B1 导出时预灌，评测零成本
- corpus 向量：B1 导出时预灌（full-content 或 chunk），评测零成本
- 换嵌入模型：首次 run 时计算并缓存，后续命中

## 七、分层架构

```
┌─────────────────────────────────────────────────────┐
│  Project 创建层（B1）                                │
│  ExportStrategy → query + corpus [+ chunks] + 向量   │
│  每个 project 自洽，冻死后不改                         │
└─────────────────────┬───────────────────────────────┘
                      │ eval.db（冻死）
                      ▼
┌─────────────────────────────────────────────────────┐
│  标注层（B2/B3）                                     │
│  读 query + corpus → LLM 打分 → 人工复核              │
│  → ground_truth（corpus_id 始终指向 parent）          │
└─────────────────────┬───────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────┐
│  评测层（B5）                                        │
│  SearchEngine 接口 → YAML 配置驱动                    │
│  chunk 模式自动按 parent 去重                          │
└─────────────────────────────────────────────────────┘
```

## 九、总结

评测引擎核心设计原则：

1. **配置驱动**：搜索策略 = YAML config
2. **单层抽象**：只关心「怎么搜」，不关心「怎么切」「query 怎么来」
3. **chunk 透明**：搜子语料 → 去重归父 → 返回 parent ID，标注结果始终指向 parent
4. **只读消费**：不修改冻死习题集，只产出报告
