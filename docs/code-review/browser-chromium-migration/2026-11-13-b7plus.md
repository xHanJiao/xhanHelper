## 问题清单

### P1（建议挡真机验收）

1. **`download` 请求特征的来源页永远是用户当前激活 tab，不是 agent 操作的那个 tab**
   - 位置：`Shared/Tools/BrowserToolProvider.swift:317-320`（dispatch）→ `:995`（`handleDownload` 无 `tabId`）→ `:1110`（`let srcSession = session ?? activeSession`）
   - 现象：`handleDownload` 调到 `runDownload` 时不传 `session`，于是 UA / Referer / Cookie 全取自 `activeSession`。而 agent 标签恒不抢 UI 激活（`:1623` 附近 `activate = !isAgent && ...`），用户没在浏览面板就该 tab 时：① `activeSession` 是另一页 → CEF tab 的 cookie 根本取不到（WK 的 session 拿 WK 库，CEF 的拿 CEF 库，本就互不相通）；② 用户根本没开浏览面板 → `srcSession == nil` → 匿名请求 + 默认 UA；③ Referer 是**别的页**，bilibili/抖音这类签名 URL 会继续 403。
   - 为什么是问题：这正是本批交付的"CEF 下载带 Cookie / 需登录媒体不再 403"，也是文档 `browser-chromium-migration.md:746` 写进 B7+ 验收的那一条；而唯一能走通的场景只剩"用户正盯着那个 CEF tab"。文档 `:484` 的表述（"CEF 的 `download` 现在带 Cookie"）在当前实现里只对一半场景成立。
   - 建议：`agent_browser_download` schema 加可选 `tabId`（与其它工具同形），dispatch 里用 `sessionFor(args)` 解析后透传 `runDownload(session:)`；无 `tabId` 且 `context.owner != nil` 时退到 `lastAgentTabByOwner[owner]`。改动很小，`runDownload` 已有 `session` 参数，不需要再动下载链。

### P2（本批内修）

2. **滚动位置：保存改成异步 `Task` 后，切回太快会读到旧值/nil，且 restore 的 nil 分支既不重试也不记日志**
   - 位置：`BrowserToolProvider.swift:2372-2391`（save 起 `Task`）、`:2395-2402`（restore 首跳 `guard let y = session.savedScrollY ... else { return }`）
   - 现象：`switchActiveTab` 同步发起 `saveScrollPosition` 后立刻为**新** tab `scheduleScrollRestore`（120ms 后开始）。CEF 的 `evaluateJS` 是渲染进程往返（最多 10s 超时），A→B→A 这种快速来回时 restore 可能早于 save 落地；`savedScrollY` 还是 nil → `guard` 直接 return，**没有后续重试**，页面停在顶部，用户看到的是"滚动位置没恢复"。
   - 为什么是问题：这是本批主推的交付点之一，且 CEF 的往返比 WK 慢，命中概率比改造前更高（改造前同样是异步回调，但少一层 `Task` 调度）。
   - 建议：给 restore 的 nil 分支加"再等一轮"（`savedScrollY == nil && attempt < N` 时继续 `scheduleScrollRestore`），或在 `saveScrollPosition` 里用一个 `scrollSaveTasks: [String: Task<Void, Never>]` 记住在飞的保存、切回时先 await 它。前者 3 行。

3. **`try? JSONSerialization` 解析失败会"吞错 + 抹掉已经存好的位置"**
   - 位置：`BrowserToolProvider.swift:2381-2387`
   - 现象：`guard let obj = (try? JSONSerialization...) as? [String: Any], ... else { session.savedScrollY = nil; return }` —— 解析失败 / 类型不是 String 时走 `text = ""` → 解析失败 → 进 `else`，把上一次成功保存的 `savedScrollY` 一起清空，且没有任何日志。
   - 为什么是问题：违反"没有允许忽略的错误，只有已记录的有意降级"；且与"y<=0 表示本来就没滚动"的正常分支混在同一个 guard 里，无法区分。
   - 建议：拆两层 —— 解析失败 `LogBuffer.shared.diag` 后 **return（保留旧值）**；只有 `y <= 0` 才 `savedScrollY = nil`。

4. **媒体探测失败 = 永久保活（WK 语义回归）**
   - 位置：`BrowserToolProvider.swift:173-190`（`verifyKeptAliveTabs`）、`:191-200`（`probeMedia` 失败返 nil）
   - 现象：改造前 WK 侧 `hasMedia = (error == nil && result == true)` —— JS 报错会被当作"没媒体"，摘保活 + `pauseAllMediaPlayback`；现在 `nil` 让调用方"保持现状"，于是 JS 崩了/页面坏了的 tab **永久留在视图层级**，且每 30s 打一条 `diag` 日志，没有次数上限。
   - 为什么是问题：一个永不返回 false 的 tab 会长期占用一个渲染进程/合成资源（这正是 keep-alive 想避免的），日志也会持续刷。设计意图（"别误摘保活"）是对的，缺的是兜底。
   - 建议：给 session 加一个 `mediaProbeFailures` 计数，连续失败 N 次（如 3）后按"无媒体"处理并记一条 `info`；或对失败也沿用"暂停但不摘保活"的中间态。

5. **CEF 取 Cookie 的"空结果/超时"全程静默**
   - 位置：`xHelperMac/CEF/CefBridge.mm:1110-1137`（`!_browser` 分支、3s 兜底）、`Shared/Services/BrowserPage.swift:356-367`（`compactMap` 丢掉造不出来的 cookie 不报）
   - 现象：manager 为 nil、`VisitUrlCookies` 返回 false 都有 `NSLog`，但**最常见**的两种"拿到 0 条"没有任何记录：① 3s 超时兜底（`finish(@[])`）；② `_browser` 还没建好时直接 `completion(@[])`。Swift 侧把 CEF 字典转 `HTTPCookie` 失败（domain 为空、name 非法）也是 `compactMap` 静默丢。
   - 为什么是问题：这是"403 排查"的唯一线索。现状是下载悄悄退化成匿名请求，用户只看到 403/权限错误，代码里查不到原因 —— 属于"明知失败却当没发生"。
   - 建议：3s 兜底那条 `NSLog` 一次（带 url）；`_browser == nil` 分支也 `NSLog` 一次；Swift 侧对 `HTTPCookie(properties:)` 返回 nil 的条目 `LogBuffer.shared.diag` 一条（带上 domain/name）。

6. **设置页内核开关对"点过换内核按钮"的站点无效，文案没提**
   - 位置：`xHelperMac/App.swift:1457-1470`、`Shared/Services/BrowserEngineRouter.swift:73-79`（`EnginePreferenceStore` 优先于默认引擎）、`Shared/Views/BrowserTabView.swift:225`（工具栏按钮写入偏好）
   - 现象：用户把设置切成"兼容（WebKit）"，但任何之前点过 tab 工具栏"换内核"的站点仍按偏好表走 CEF；界面只说"只影响之后新开的标签"。
   - 为什么是问题：开关从 dev-only 转正后，这是用户最可能报的"切了不生效"。作者已按"起不来会自动降级"做了 Toast，但没覆盖"被站点偏好覆盖"这条更常见的原因。
   - 建议：caption 补一句"对已单独指定过内核的站点无效"；或者顺手在设置里加「清除站点内核偏好」（`EnginePreferenceStore` 加一个 `reset()`，一行）。

7. **`press` 的真键盘路径没有辅助功能权限闸门，而唯一的权限检查代码随 `cgClick` 一起删掉了**
   - 位置：`BrowserToolProvider.swift:439-453`（WK 分支直接 `pressKey`）、`Shared/Services/CGEventInput.swift:13-24`（`isTrusted` / `requestPermission` 已无调用方）
   - 现象：未授权辅助功能时 `CGEvent.post` 静默无效，工具仍返回 `{"pressed": true, "real": true}`；`isTrusted()` / `requestPermission()` 成了死代码。
   - 为什么是问题：① 工具谎报成功（与 `docs/bugs/065` 同性质，代码里已有先例）；② 留一对没人用的权限 API，下次谁都不知道 `press` 到底需不需要授权。注意这条是**既有缺陷**，但本批删除动作让它暴露出来。
   - 建议：`press` 的真键盘分支补 `guard CGEventInput.isTrusted()`，未授权时 `requestPermission()` 并返回可读错误（文案照抄原 `cgClick` 那句）；这样两个 helper 也就重新有主了。

### P3（记账即可）

8. `CefBridge.mm:711-740`：`Visit` / 析构里创建 `NSMutableDictionary` / `NSString` / `[items_ copy]`，没有 `@autoreleasepool`。CEF 回调线程不保证有池（即便有，显式包一层成本≈0），否则每次取 cookie 泄露一批 autoreleased 对象。建议把 `Visit` 方法体包进 `@autoreleasepool {}`。
9. `BrowserPage.swift:70-80`：`BrowserCookieMatching.matching` 只做 RFC 6265 的 domain-match + secure，不看 `path`（CEF 那边现在把 `path` 也带回来了）。同 host 不同 path 的 cookie 会被一并发出，属宽松偏差；真要收严就在 matcher 里补 path-prefix 规则。另外它现在住在 `import WebKit` 的文件里，进不了 SwiftPM 纯逻辑靶（`Package.swift` 里没列），**安全相关的匹配逻辑零测试** —— 建议挪成独立小文件 + 挂到 `BrowserEngineCore` 靶补 4~5 条断言（`a.example.com` / `.example.com` / `example.com.evil` / secure over http / 空 host）。
10. `BrowserPage.swift:356-367`：`(item["secure"] as? Bool) == true` 依赖 `NSNumber(int)` → `Bool` 的宽松桥接；写成 `(item["secure"] as? NSNumber)?.boolValue == true` 更稳（这里判错的方向是"把 Secure cookie 发到 http"，属安全侧）。`domain` 为空时 `HTTPCookie` 造不出来 → 静默丢，见 P2-5。
11. 陈旧注释 / 文档，容易误导后来人：
    - `BrowserToolProvider.swift:1615-1618`：仍写"仍走 WK 的只剩真实鼠标注入（cg_click/cg_drag）"；
    - `BrowserToolProvider.swift:2822-2823`：`webView` 注释仍把"JS/下载/快照"列为 WK 专属；
    - `docs/security/red-team-test-page.html:46`：测试页仍指示调用 `agent_browser_cgclick`（用例 5 已在 `red-team-browser.md` 标注作废）；
    - `docs/design/chat-stop-and-tool-risk-levels.md:99`：旧等级表样例里还有 `cgclick` / `cgdrag`（尾部有后续变更，但代码块本身没改）。
12. `BrowserToolProvider.swift:269`：`press` 的 schema 描述仍写"真实按键（Enter 等）仅对屏幕可见标签生效"，而 CEF tab 走 JS、后台也能用 → 模型会自我限制、绕开 CEF tab 上的按键。建议改成"WK tab 的真实按键仅对屏幕可见标签生效；CEF tab 走合成事件"。
13. `BrowserToolProvider.swift:2431-2434`：CEF 的 `pauseMediaScript` 只遍历 `document.querySelectorAll('video,audio')`，覆盖不到 shadow DOM 内、跨域 iframe 内的 media（WK 的 `pauseAllMediaPlayback` 是全覆盖）。作为"CEF 没有原生 API"的替代可以接受，值得在注释里写明边界。
14. `App.swift:1461`：`isCefUnavailable` 时 `BrowserTabView` 的换内核按钮会置灰，但设置页仍可选"Chromium（CEF）"（点了只会逐个 tab 走 Toast 降级）。建议同样的条件下 disable 该 tag 或在 caption 里显式说明。
15. `BrowserToolProvider.swift:2397`：`scheduleScrollRestore` 放弃时仍是 `print("[BrowserDiag] ...")`（Release 也打、不走 LogBuffer），与同文件其它诊断日志口径不一致（既有问题）。

## 已确认没问题

- **continuation 生命周期**：`XHCefCookieCollector` 析构经 `RunOnMain`（非主线程则 `dispatch_async`）、3s `dispatch_after`、`VisitUrlCookies` 失败分支**三条路径都在主线程**，`__block BOOL finished` 无数据竞争；`finished` 去重保证 `withCheckedContinuation` 不会被 resume 两次；每次调用都会在 3s 内至少 resume 一次（visitor 不析构也有兜底），下载不会挂死。
- **visitor 内存/线程**：`items_` 只在 CEF IO 线程的 `Visit` 里写、在析构里读，顺序由 CEF 的 refcount 释放保证；`ARC` 已开（`CLANG_ENABLE_OBJC_ARC = YES`），strong ivar / block 由编译器释放；`GetGlobalManager` 按文档可在任意 browser process 线程调用，且与 `CreateBrowser(..., nullptr, nullptr)` 用的是**同一个全局 request context**，cookie 库不会串。
- **浏览器销毁/关闭期间**：`cookiesForURLString` 只在一开始看 `_browser`，之后走的是全局 manager，不碰 `_browser`；tab 关闭不影响已发出的 visit，回包被 `finished` 吃掉。
- **cookie 域匹配不会多送**：CEF 侧 `VisitUrlCookies(url, ...)` 已按 URL 过滤，Swift 再过度一次 `matching` 只会更窄；WK 侧是从全量 store 里过滤（与改造前同一套规则）。重复过滤不构成跨域泄露。下载链的危险扩展名（URL + 自定义文件名）、魔数媒体校验、`sanitizeFileName` 全部保留未动。
- **`press` 闸门**：`tool == press && session.webView != nil && 非激活` 三个条件同时成立才拒；CEF tab 走 JS 合成事件、WK 后台 tab 仍被拦，逻辑自洽。
- **keepAlive 对 CEF 有效**：`RightSidebarView.swift:516-527` 按 id 把保活 tab 以 `opacity(0)` 留在视图层级，CEF 视图仍在窗口里继续出帧；不在保活集合时掉回 `parkInHiddenWindowIfNeeded` 的隐藏窗口，页面不销毁。
- **`verifyKeptAliveTabs` 的并发**：`for tabId in rs.keptAliveTabIds` 遍历的是 Set 副本，真正的 `remove` 发生在下一个主 actor 时间片的 `Task` 里，不会"遍历中改集合"。
- **WK 原路径语义**：`pauseMedia` 对 WK 仍只调 `pauseAllMediaPlayback()`（提前 return），没有多打一次 JS `pause`；agent tab 切走仍是"直接暂停"。
- **删除删干净**：`cgclick` / `cg_drag` 在 Swift（schema / `shortNames` / 风险表 / dispatch / `CGEventInput` / `BrowserActivityCenter` 确认文案 / `userTabWriteTools`）、Go 服务端（`server/` 下无任何引用，含 `tool_excludes`、plan 只读白名单、`subagent.go`）、前端与 `Package.swift` 测试靶均无残留；`cefUnsupported` / `cefUnsupportedCGEvent` 两个常量删净、无悬空引用。
- **测试**：`ToolConfirmPolicyTests.swift` 只删了 cgclick/drag 两条断言、改名，其余断言与现工具名单一致；tests 目录里没有其它引用被删工具的 fixture。
- **设置开关不会"prod 没引擎"**：`defaultEngineKey` = `xhan_browser_engine_<env>`，`env` 在 `BrowserEngineRouter`（`#if DEBUG → dev`）与 `LocalPaths.env` 判定一致；`@AppStorage` 的默认值 `"cef"` 与 `defaultEngine`（未设置 → cef）一致；`project.pbxproj` 的 Debug/Release 两段（`:494` / `:552`）都带 CEF 搜索路径与 `-lcef_dll_wrapper`，并有 Bundle CEF 构建阶段，prod 不是"有这个选项没这个引擎"。
- **`fetchPageResourceJSON` 的 CEF 分支**：按 `page.wkWebView === wv` 反查 session，CEF 侧永远为 nil，所以该函数实际只走 WK —— 属"多写了一条不会走的分支"，不是缺陷（真正的 CEF 原生请求入口是 `runDownload`）。
