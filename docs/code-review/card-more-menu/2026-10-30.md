### P2 - Medium

#### 1. `client/xHelper/xHelper/Shared/Services/ArtifactOpenCoordinator.swift:148` 下载的 `.html` 与右栏不是同一份版式

- `exportPDF` 走了 `injectingBaseline(html)`（`:162`），`downloadHTML` 把服务端原文直接落盘。
- 版式基线是**加载时注入、不写进库**的（`HTMLArtifactView.swift:3-8` 注释明确），所以模型页没写 `font-family/size/padding` 的那些，用 Safari 打开会退回 Times + 零边距。
- 与设计文档 §5 验收项「下载的 `.html` 用 Safari 打开观感与右栏一致」（`design.md:112`）直接冲突。
- **改法**：`try injectingBaseline(html).write(to: url, atomically: true, encoding: .utf8)`（一行）；若产品上确实想下载"原始产物"，就把那条验收改掉，别让两条路各说一套。

#### 2. `ArtifactOpenCoordinator.swift:144-166` 先拉正文、后弹保存面板 → 大页面点下去像没反应

- 灵阅产物典型 4.8–19KB，内联多图能到近 8MB（`ArtifactOpenCoordinator.swift:13` 自己写着这个量级）。当前顺序：点菜单 → 静默 `await getArtifact` 数秒 → 才出 `NSSavePanel`，中间无 spinner / toast。
- 与项目已有的教训同形（`design.md` §9.8「拉完才开 tab 在慢链路上就是纯静默」）；`DocumentSelectionCoordinator.download` 是**先面板后写盘**的，两条路行为不一致。
- 另：无重入守卫，连点两次会发两次 `getArtifact`（`copyShareLink` 同理，见 P3-2）。
- **改法**（二选一）：先 `saveURL` 拿目标 URL 再 fetch（对齐文档导出）；或点下立刻 toast「正在准备…」。

#### 3. `client/xHelper/xHelper/Shared/Views/CardView.swift:207`、`:221` `⋯` 对比度不达标 + 无无障碍名

- 12pt 图标做可点击控件，非文本对比度要求 3:1；`assistantText` 40% 叠在近白卡片上约 2.4:1，深色下同为 40%。
- `Menu` 的 label 是一张裸 `Image(systemName: "ellipsis")`，只有 `.help("更多操作")`（macOS 上是 tooltip），**没有 `.accessibilityLabel`** → VoiceOver 拿不到名字。
- 设计文档 §5 已把"深浅色各看一次对比度"列为验收，说明取值本来该当场拍。
- **改法**：opacity 提到 ~0.55（hover 态不动），补 `.accessibilityLabel("更多操作")`。

#### 4. `client/xHelper/xHelper/Shared/Services/DocumentPDFExporter.swift:41-46` 大产物导 PDF 可能漏图

- `renderPDF` 在 `didFinish` 后固定等 350ms（`:144`）就开印，注释写明"留给 marked 注入 + 图片解码"。
- 文档导出面对的是外链图（非持久 store，裂图属预期）；灵阅是**内联 base64 大图**，8MB 页面的解码时间明显超过 350ms。本次把同一条管线复用到了更重的输入上。
- 不是本次引入的缺陷，但需要真机验：用最大的那张产物导一次，看图片是否齐。若漏，最小改法是给 `exportHTML` 加等待倍率，或在打印前轮询 `document.images` 全部 `complete`，**不要**改文档那条链路的行为。

### 7.2 新增 findings（均 P3）

#### P3-1 `CardView.swift:209` 0.55 只是刚好卡在 3:1，且卡片底不是纯色

#### P3-3 `DocumentPDFExporter.swift:121-125` JS 里 `catch (e) {}` 静默吞掉 decode 失败
