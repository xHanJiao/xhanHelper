# 状态页更新 Prompt 草案 v1

> 状态：草案，待实测调优 | 用途：嵌入 ThemeAnalyst 的 `updated_state` 生成逻辑

---

## 一、设计目标

状态页是**跨轮次传递的主题记忆**。每次 ThemeAnalyst 分析完一个主题后，产出一份新的状态页覆盖旧版。下一次分析时，ThemeAnalyst 读状态页 + 增量数据，而不是翻全量历史。

好状态页的目标：
- 让下一轮 ThemeAnalyst 不用回溯原始数据就能理解主题现状
- 保留规律、里程碑、待跟进事项等「长期有效」的信息
- 自动淘汰过期、失效、已解决的条目
- 篇幅始终可控（不超过 500 字）

---

## 二、更新 Prompt（嵌入 ThemeAnalyst 的 hot_run 路径）

```
## 状态页更新

你需要维护一份主题状态页。目的是让下一次分析时，另一个 LLM 实例（可能是你，也可能不是）在不看原始数据的情况下，仅凭这份状态页就能快速理解主题的现状。

### 更新规则

1. **继承有效信息**：上一轮状态页中仍然成立的规律、里程碑、待跟进事项，保留并更新措辞
2. **覆盖过时信息**：已被新数据否定或已解决的条目，用最新事实替换
3. **标注时间**：每条关键信息标注大致时间（「4月初」「过去3个月」「5月14日」），供下一轮判断时效性
4. **控制篇幅**：不超过 500 字。超过时优先保留最新、最重要的信息，其余可删减为一句话概括
5. **标记待跟进**：如果发现悬而未决的事项（如「等字节面试结果」），显式标为「⏳ 待跟进」
6. **移除或降级过期条目**：超过 3 个月且本次分析未再出现的信息，移除或在末尾单列一行「📦 历史：...」简要标记
```

## 三、Few-Shot 示例

### 示例 1：职业规划（有进展更新）

**上一轮状态页：**
```
用户处于求职阶段（2026年4月起）。目标：6月底前拿offer。已投30家，面3家（某大厂一面过了等终面，某独角兽一面过，第三家等通知）。5月初聊过表示继续投。⏳ 待跟进：终面结果。
```

**本次增量数据：**
- 5/10 聊天："又投了5家，2家约了面试下周"
- 5/12 笔记：记录了面试准备清单（算法、系统设计、行为面）
- 5/14 聊天："终面安排在下周了，紧锣密鼓准备中"

**更新后状态页（LLM 产出）：**
```
求职进行中（更新至5月14日）。目标：6月底前拿offer（还剩约6周）。
进度：已投约35家，累计面试5家。已过2家一面（某大厂、某独角兽），1家终面进行中，2家下周约面。
新进展：面试准备清单已整理（参见笔记），下周有2家面试。
⏳ 待跟进：终面结果、下周2家面试。
⚠️ 关注：时间窗口收窄中，如果当前流程都不顺利，可能需要扩大投递面做备选。
```

**点评**：状态页比上一轮精炼了——去掉了重复信息，新增了面试进展和时间压力两个可跟踪的维度。600 多字的原始对话被压缩为 120 字摘要。

### 示例 2：日用品补充（规律被打破后更新）

**上一轮状态页：**
```
桶装水：约28天/次，上次4月20日（4桶）。厨房纸巾：约45天/次，上次4月1日。饮用水：约20天/次，上次4月15日。
```

**本次增量数据：**
- 5/03 记账：厨房纸巾 ¥35
- 5/05 聊天："最近天热，水喝得比以前快了"
- 5/10 记账：桶装水 4桶 ¥48

**更新后状态页（LLM 产出）：**
```
桶装水：周期缩短至约20天（5月高温加速消耗），上次5月10日，预计5月底前需补充。
厨房纸巾：周期约32天（vs 历史45天，略有加快），上次5月3日，下次约6月初。
饮用水：上次记录仍为4月15日，本次未出现购买，需确认是否已改用桶装水替代。
📦 历史：一季度所有消耗品周期偏长（冬季），5月后普遍加速。
```

**点评**：识别了「规律被打破」（天热加速消耗），标记了数据异常（饮用水可能被替代），历史数据没有直接删而是降级到 📦 行。状态页不是数据复述，而是**解释变化**。

### 示例 3：关系思考（碎片化聊天中的总结）

**上一轮状态页：**
```
（无，cold_start）
```

**本次增量数据：**
- 4/28 聊天：用户提到和爱人因为家务分配吵了一架，事后和好了，用户反思「觉得自己当时太冲，应该先听对方说完」
- 5/02 聊天：用户说最近在尝试「每天下班回家先聊10分钟再各干各的」，感觉关系有改善
- 5/09 记忆提取：「用户和爱人约定每天下班后先交流10分钟」

**更新后状态页（LLM 产出，cold_start → 首次状态页）：**
```
关系维护（自4月底开始关注）。触发事件：4月底因家务分配争吵，事后和好，用户反思「应先倾听」。
当前状态：已建立「每天下班先聊10分钟」的约定，5月初反馈关系有改善。
关键认知：用户认为自己倾向「急于表达而非倾听」，这是自我觉察的早期信号。
建议后续关注：约定是否持续、用户是否在类似情境中重复冲动模式。
```

**点评**：cold_start 从 3 条碎片中提取出一个完整的叙事弧线（事件→反思→行动→效果）。同时标记了一个「后续关注」方向，下次 hot_run 时 ThemeAnalyst 可以针对性检索。

### 示例 4：无显著变化（应该返回空的状态页更新）

**上一轮状态页：**
```
职业规划：求职中，目标6月底。已面5家，下周2家待面。准备清单已完成。
```

**本次增量数据：**
- 没有任何与求职相关的聊天、笔记或记录（用户这周都在聊别的事）

**更新后状态页（LLM 产出——基本不变）：**
```
求职中（5月14日后无新进展）。目标6月底，已面5家。⏳ 待跟进：下周面试结果（如有）。
```

**点评**：没有新数据时就保持精简，不要硬编。状态页比上一轮更短了——因为旧信息的时效性在自动衰减，不重要的一笔带过。

## 四、常见失败模式（实现时注意）

| 失败模式 | 表现 | 预防 |
|----------|------|------|
| 状态页膨胀 | 每轮都追加新信息从不删旧，三个月底后状态页 2000 字 | 硬限制 500 字 + 引导 LLM 精简 |
| 信息丢失 | 删掉了「面试转化率低」但这事还没解决 | 要求保留所有 ⏳ 待跟进条目，除非已解决 |
| 复读机 | 状态页只是把原始数据复述一遍，没有提炼 | 强调「解释变化」而非「复述数据」 |
| 过于抽象 | 状态页变成「用户正在求职」一句话，丢了所有细节 | few-shot 示范了信息密度的平衡点 |
| 时间漂移 | 「上周」「最近」「过段时间」——下次根本不知道是什么时候 | 要求所有时间用绝对日期或「4月初」等可定位描述 |
