# B3 标注前端设计方案

> 2026-06-15 · 离线试题集 Phase B3
>
> 在前端 Admin 区域新增检索评测标注页面，对 B2 产出的 LLM 预标注结果进行人工复核修正。

---

## 一、设计目标

| 目标 | 说明 |
|------|------|
| **复核修正** | 逐条查看 LLM 预标注，修改错误的评分、补上漏掉的 |
| **浏览查看** | 浏览语料库、标注记录、项目统计 |
| **本地运行** | eval.db 只在本地，不走线上，无需联网 |
| **管理集成** | 挂载在 Admin 导航下，与监控看板平级 |

## 二、前端设计

```
│  ☐ #005 买房    │  │ 外卖比堂食贵               2 ● ●○ │ │
│  ☐ #006 股票    │  │ 减肥计划                   0 ● ●● │ │
│  ...            │  │ 5月食品支出概览             3 ● ●○ │ │
│                 │  │ ... 共 20 条候选              │ │
│  [上一页][下一页] │  └─────────────────────────────────┘ │
│                 │                                      │
│  共 1496 条      │  备注：                              │
│  已标 10 条      │  [____________]                      │
│                 │                                      │
│                 │  [保存修改]  [标记为已审核]   [跳过]    │
└─────────────────┴──────────────────────────────────────┘
```

**交互细节**：

- **左侧列表**：
  - 默认显示未标注 query（排除已有 ground_truth 记录并标记为 reviewed 的）
  - 搜索框：模糊匹配 query 内容
  - 状态筛选：`全部` / `未审核` / `已审核` / `已修正`
  - 分页加载，每页 50 条
  - 点击选中一条，右侧加载详情

- **右侧详情**：
  - 顶部：query 文本 + 元信息（来源、时间、标注状态、已标注 session 列表）
  - 中间：20 条 corpus 候选列表（来自 LLM 预标注或 cosine 结果），每行显示 corpus 内容摘要 + 当前评分
  - 评分控件：5 个 radio 按钮式的 slot，0~4，点击切换
  - 备注框：可写修改原因
  - 操作按钮：
    - **保存修改**：PATCH 当前标注，可修改任意条
    - **标记为已审核**：将该 query 在 `annotation_session_queries` 的 `label_status` 改为 `reviewed`
    - **跳过**：不保存修改，切换下一条

**评分交互控件**：

```
○ ○ ○ ○ ○    → 0（完全无关）
● ○ ○ ○ ○    → 1（话题相近）
● ● ○ ○ ○    → 2（弱相关）
● ● ● ○ ○    → 3（相关）
● ● ● ● ○    → 4（完美命中）

悬停显示档位名称，点击即选。
```

**数据来源**：
- 列表：`GET /api/admin/eval/projects/:project/queries?status=unreviewed&limit=50&offset=0`
- 详情：`GET /api/admin/eval/projects/:project/queries/:id`
- 保存：`PATCH /api/admin/eval/projects/:project/queries/:id`

## 三、后端 API

### 3.1 实现架构

```
controller/eval_admin_handler.go     # HTTP Handler
    │
    ▼
internal/eval/repo.go                # SQLite 查询层
    │
    ▼
server/data/eval/<project>/eval.db   # 数据源
```

`EvalAdminHandler` 接受项目名，打开对应 `eval.db`，调用 `eval.Repo` 方法查询。不经过 GORM，直接 `database/sql`。

所有 API 响应统一用 `view.JSONOK(c, data)` 和 `view.JSONError(c, code, msg)`：
- 成功：`{ "status": "ok", "data": { ... } }`，HTTP 200
- 错误：`{ "status": "error", "errorCode": 500, "errMsg": "..." }`

### 3.2 注册方式

**新增文件**：`server/internal/controller/eval_admin_handler.go`

**路由注册**（在 `reflection_routes.go` 的 admin group 中追加）：

```go
type EvalRoutesConfig struct {
    AuthMiddleware  gin.HandlerFunc
    AdminMiddleware gin.HandlerFunc
    Handler         *controller.EvalAdminHandler
}

func RegisterEvalRoutes(rc EvalRoutesConfig) {
    admin := rc.R.Group("/api/admin")
    admin.Use(rc.AuthMiddleware, rc.AdminMiddleware)
    {
        eval := admin.Group("/eval")
        {
            eval.GET("/projects", rc.Handler.ListProjects)
            eval.GET("/projects/:project/stats", rc.Handler.GetStats)
            eval.GET("/projects/:project/queries", rc.Handler.ListQueries)
            eval.GET("/projects/:project/queries/:id", rc.Handler.GetQueryDetail)
            eval.PATCH("/projects/:project/queries/:id", rc.Handler.UpdateAnnotations)
            eval.GET("/projects/:project/corpus", rc.Handler.ListCorpus)
            eval.GET("/projects/:project/annotations", rc.Handler.ListAnnotations)
        }
    }
}
```

`appinit/router.go` 中实例化 handler 并调用 `RegisterEvalRoutes`。

如需本地开发时免 admin 验证，可在 handler 中检查 `cfg.Server.Mode == "debug"` 自动放行。

分页列表，支持搜索和状态筛选。

**参数**：
- `limit` (default 50)
- `offset` (default 0)
- `keyword` (搜索 query 内容模糊匹配)

**响应**（view.JSONOK）：
```json

        "created_at": "2026-05-20T...",
        "labeled_count": 20,
        "reviewed": false
      }
    ],
    "total": 1496
  }
}
```

#### `GET /api/admin/eval/projects/:project/queries/:id`

单条 query 详情，含所有标注。

**响应**（view.JSONOK）：
```json
{
  "status": "ok",
  "data": {
    "query": {
      "id": "xxx",
      "content": "我上个月吃饭花了多少",

      "created_at": "2026-05-20T..."
    },
    "annotations": [
      {
        "corpus_id": "aaa",

        "relevance": 4,
        "label_source": "llm",
        "labeled_at": "2026-06-15T..."
      }
    ],
    "review_status": "prelabeled"
  }
}
```

#### `PATCH /api/admin/eval/projects/:project/queries/:id`

修改标注 + 标记审核状态。

**请求体**：
```json
{
  "annotations": [
    { "corpus_id": "aaa", "relevance": 3 },
    { "corpus_id": "bbb", "relevance": 0 }
  ],
  "review_status": "reviewed",
  "notes": "LLM 把吃饭相关的 3 条给了 4 分，改为 3"
}
```

- `annotations`：要修改的标注列表，只发变化项。后端 `INSERT OR REPLACE`，`label_source` 改为 `corrected`。
- `review_status`：可为 `reviewed` 或 `finalized`，更新 `annotation_session_queries.label_status`（对当前 session）
- `notes`：写入 `eval_metadata` 或 `eval_ground_truth.notes`

**响应**（view.JSONOK）：
```json
{ "status": "ok", "data": null }
```

#### `GET /api/admin/eval/projects/:project/corpus`

分页语料列表。

**参数**：
- `limit` / `offset`
- `keyword` (搜索内容)
- `type`：`all` / `note` / `memory`
- `topic` (按主题过滤)

**响应**（view.JSONOK）：
```json
{
  "status": "ok",
  "data": {
    "corpus": [
    {
```

- `label_source`：`all` / `llm` / `corrected`

## 四、数据查询层

`server/internal/eval/repo.go` — 对 `eval.db` 的 SQLite 查询封装。

```go
package eval

type Repo struct {
    db *sql.DB
}

func OpenRepo(dbPath string) (*Repo, error) { ... }

// 项目
func (r *Repo) ListProjects() ([]ProjectInfo, error) { ... }
func (r *Repo) GetStats() (*Stats, error) { ... }

// Query 查询
func (r *Repo) ListQueries(keyword, status string, limit, offset int) ([]QueryInfo, int, error) { ... }
func (r *Repo) GetQueryDetail(queryID string) (*QueryDetail, error) { ... }
func (r *Repo) UpdateAnnotations(queryID string, anns []AnnotationUpdate, status string, notes string) error { ... }

// Corpus 查询
func (r *Repo) ListCorpus(keyword, sourceType, topic string, limit, offset int) ([]CorpusInfo, int, error) { ... }

// 标注记录查询
func (r *Repo) ListAnnotations(queryKeyword string, relevance, labelSource string, limit, offset int) ([]AnnotationRecord, int, error) { ... }
```

所有方法直接查 SQLite，不依赖 GORM。

## 六、本地开发说明

- eval.db 路径：`server/data/eval/<project>/eval.db`
- 前端开发时 `npm run dev` 走 `localhost:5173`，API 代理到 `localhost:8088`
- 需在 `vite.config.js` 中 `/api` 代理已配置，无需额外改动
- AdminOnly 中间件可本地跳过：在 `debug` 模式下直接放行

## 七、总结

B3 做完后，你的工作流：

1. 浏览器打开 `http://localhost:5173/admin/eval`
2. 选项目 → 切到「逐条审核」Tab
3. 一条条看，不对的改，打勾保存
4. 标完后看「标注概览」确认进度

标注数据存本地 eval.db，不上传、不同步。
