# 跨缩进列表项的划线保存成功却画不出来 —— 投影没剥掉缩进的块标记

## 问题表现

在文档里选中**跨过嵌套列表项**的几行字划线，波浪线**从未出现**（不是画完又消失）；抽屉里那条记录在「全部」里正常存在、不在「已失活」里，点它会 toast「这条划线在当前正文里定位不到」。

用户观感是「选了一行字并划线，然后直接失活了，虽然没有任何修改」。

## 先排除的两个怀疑

- **不是 orphan**：dev 库里三条记录 `orphaned=0`、`quote_rewritten=0`，服务端认为锚得好好的。
- **不是客户端选区算错**：客户端 `flatOffset` 对「容器是文本节点」的选区是精确的；服务端夹逼出来的右边界由客户端发的 suffix 决定，反推选区终点确实落在第四项开头（用户确认拖拽越过了 3 个列表项）。

## 根因：缩进空格把「行首」状态抹掉了

文档里是缩进嵌套列表：

```
- 已产出素材共 4 条，均附逻辑点评：
  - 信息论角度：无意义对话信息熵更高，更难被压缩
  - 「所有男人必定都当过孙子」——双关硬撑：「孙子」为骂人语
```

`service/document_anchor.go` 的 `project()` 空白分支原本是 `lineStart = r == '\n'` —— 换行**之后**那两个缩进空格会把 `lineStart` 重置成 `false`，于是紧随的 `-` 不再被判为块标记，**原样留在投影里**：

| 侧 | 同一段的纯文本 |
|---|---|
| 服务端 `project()` | `点评： - 信息论角度：…` |
| 客户端 `fold()`（DOM，marked 已渲染成 `<ul>`） | `点评： 信息论角度：…` |

于是跨嵌套列表项的选区：rung 1（源文精确匹配）因为源文里是 `\n  - ` 必然失败；rung 2（投影整段匹配）因为多出来的 `- ` 也失败；**掉进 rung 3 夹逼**。

rung 3 会**改写用户的 quote**（`Span.Fuzzy=true`，`Quote` 变成投影切片），回来的文本带着 `" - "`：

```
硬撑：「孙子」为骂人语 「一个人能走多远」…        ← 客户端发的
硬撑：「孙子」为骂人语 - 「一个人能走多远」…      ← 夹逼改写后回来的（库里存的）
```

客户端 `locate()` 拿这个 quote 去 DOM 里 `indexOf`，DOM 里**根本没有 `-` 这个字符** → 永远找不到 → `wrapSpan` 不执行 → 波浪线画不出来。服务端 `orphaned=0`，所以它既不在「已失活」里，也不可能自愈。

三条记录里只有这一条肉眼可见地坏掉：另外两条的边界是列 0 的列表标记/标题，投影剥得干净、不含 `-`，客户端仍能定位。**坏掉的那条恰好是唯一跨了嵌套列表项边界的**。

## 修复

1. `project()`：行首状态跨缩进保持，只有换行能开新行。

```go
case unicode.IsSpace(r):
    if !prevSpace { push(' ', i); prevSpace = true }
    if r == '\n' { lineStart = true }   // 原：lineStart = r == '\n'
    continue
```

修完 `  - ` / `  12. ` / `  > ` 与列 0 形式一样被剥掉，投影重新等于 DOM 文本 → rung 2 接住跨界选区（quote 原样保留），rung 1 继续管项内选区。

2. 顺带修掉「偷改用户数据不留痕」：`QuoteRewritten` 只有 `RelocateAll` 在写，`CreateAnnotation` 根本没赋过值、`RelocateAnnotation` 硬写 `false`。两处都改成 `sp.Fuzzy`。

## 钉子

- `TestProjectStripsIndentedBlockMarkers` —— 缩进列表 / 缩进有序列表 / 缩进引用都要剥掉；正文里 `3 - 2` 这种行内短横要留着
- `TestLocateAcrossNestedListItems` —— 真实形状的嵌套列表 + 跨两个子项的 quote + DOM 前后文提示，断言 `Fuzzy == false`、`Quote` 原样保留、落点确实跨过了 `\n  - `
- 两条都做过**变异验证**：把 `lineStart` 改回旧写法，后者报的正是库里那条指纹 —— `走了夹逼：quote 被改写成 "…为骂人语 - 「一个人能走多远」…"`

## 留给以后的

- **不变量**：`project()`（Go）与 `fold()`（JS）对同一份正文必须给出同一条纯文本流。投影是两边唯一的公共空间，这个不变量没有跨语言测试守着，只能靠这条 bug 记录 + 两边的单测各自钉住（已写入 design.md §4.3）。
- 已知的残余不对齐（都还没咬人，先不修）：
  - 服务端 `project()` 把任何 `unicode.IsSpace` 都折叠成空格，客户端 `fold()` 只认 `' ' \n \t \r \u3000`（NBSP、`\u2028` 之类两边不一致）
  - `<hr>`（`---`）：服务端整行剥掉、不留空格，客户端 `flatten()` 在块边界补 `\n` → 折叠成一个空格
  - 前后文提示的投影从头开始 `lineStart=true`（片段起点被当成行首），片段恰好以 `- ` 开头时会多剥一次（只影响消歧打分）
- 库里那三条旧记录的 quote 已经带 `" - "`，不会被这次修复自愈（`RelocateAll` 只在正文变化时跑）。要么删掉重划，要么等下次正文被改写时自动重锚回正确文本。
