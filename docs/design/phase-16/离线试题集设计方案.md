# 离线试题集设计方案

> 2026-06-16 更新 · 基于 RAG 检索评测框架 Phase 1 细化
>
> 核心目标：构建一套**可重复、可版本管理、冻结不可修改**的检索评测数据集。
>
> **2026-06-16 更新**：`ExportStrategy` 同时决定 query 和 corpus 的构建方式。新增 `eval_corpus_chunks` 子语料表。query/corpus 形态在 Project 创建时冻结，标注和评测直接消费成品。

---

## 一、设计目标

| 目标 | 说明 |
|------|------|
| **数据驱动** | 试题源于真实用户 query，覆盖实际使用场景 |
| **可重复** | 锁死试题集后，任何检索策略改动都能回放对比 |
| **自包含** | 一个 SQLite 文件 = 一个完整数据集项目，可搬运、可 git 管理 |
| **不可篡改** | 导出数据冻死不变，标注累进式修改 |

## 二、数据集架构

### 2.1 项目概念

每个 Project 在创建时由 `ExportStrategy` 决定 query 和 corpus 的最终形态，完成后不可修改：

```
server/data/eval/
├── 2026-06-15-retrieval-baseline/      # 策略: raw query + full_content corpus
│   └── eval.db
├── 2026-07-01-chunk-sentence/          # 策略: raw query + sentence_chunk corpus
│   └── eval.db
├── 2026-07-15-with-history/            # 策略: with_history query + full_content corpus
│   └── eval.db
└── ...
```

不同 project 之间互不干扰，对比就是跑两个 project 的评测报告。

### 2.2 核心抽象：ExportStrategy

```go
type ExportStrategy interface {
    Name() string
    ExportQueries(ctx context.Context, db *sql.DB) ([]QueryExport, error)
    ExportCorpus(ctx context.Context, db *sql.DB) ([]CorpusExport, error)
}
```

**一个 Project = 一个 ExportStrategy 实现。**

| 实现 | query 产出 | corpus 产出 | 用途 |
|------|-----------|-------------|------|
| `all-past-data` | 原始用户消息（过滤短消息） | full-content 笔记+记忆 | 基线 |
| `sentence-chunks` | 原始用户消息 | 句子级 chunk 化语料 | 对比 chunk 策略 |
| `with-history` | 消息+前 N 条拼接 | full-content 笔记+记忆 | 对比历史上下文 |
| `hybrid-full` | 消息+拼接 L 条 | full-content + chunk | 混合 |

> 评测引擎（B5）不再需要 `CorpusProcessor`——corpus 形态在 B1 就定型了。

### 2.3 表结构

共 9 张表：

#### `eval_projects` — 项目注册

```sql
CREATE TABLE eval_projects (
    id          TEXT PRIMARY KEY,        -- 项目名，如 "2026-06-15-retrieval-baseline"
    name        TEXT NOT NULL,
    description TEXT,
    status      TEXT NOT NULL DEFAULT 'draft',  -- draft | annotating | locked | archived
    created_at  TEXT NOT NULL DEFAULT (datetime('now')),
    locked_at   TEXT
);
```

#### `raw_queries` — 用于检索的 query 文本（只读）

```sql
CREATE TABLE raw_queries (
    id               TEXT PRIMARY KEY,        -- UUID
    content          TEXT NOT NULL,           -- 最终用于检索的文本（ExportStrategy 产出）
    source_msg_id    TEXT,                    -- 来源 messages.id（raw 策略时有值，改写的为 null）
    source_conv_id   TEXT,
    created_at       TEXT
);
```

- `content` 是 project 创建时 `ExportStrategy` 生成的最终文本
- 标注和评测**只读此表的 content**，不需要再加工

#### `eval_corpus` — 被检索的语料库（只读，parent 级）

```sql
CREATE TABLE eval_corpus (
    id          TEXT PRIMARY KEY,
    content     TEXT NOT NULL,           -- 完整文本（full-content 模式）或摘要
    source_type TEXT NOT NULL,           -- 'note' | 'memory'
    source_id   TEXT NOT NULL,           -- 来源表原始 ID
    topic       TEXT,
    tags        TEXT,
    created_at  TEXT
);
```

#### `eval_corpus_chunks` — 子语料（仅 chunk 模式的 project）

```sql
CREATE TABLE eval_corpus_chunks (
    id          TEXT PRIMARY KEY,        -- chunk UUID
    corpus_id   TEXT NOT NULL,           -- FK → eval_corpus.id（parent）
    chunk_index INTEGER NOT NULL,        -- 0-based 序号
    content     TEXT NOT NULL            -- 句子文本
);
```

- full-content 模式的 project 此表为空
- chunk 模式：`eval_corpus` 存 parent 原样，`eval_corpus_chunks` 存每个句子
- SearchEngine 搜 chunk 向量 → 命中 chunk → 按 `corpus_id` 去重 → 返回 parent
- 向量缓存中 `source_type='corpus_chunk'`, `source_id=chunk.id`

#### `annotation_sessions` — 标注批次

```sql
CREATE TABLE annotation_sessions (
    id           TEXT PRIMARY KEY,
    project_id   TEXT NOT NULL,
    name         TEXT,
    status       TEXT NOT NULL DEFAULT 'draft',   -- draft | labeling | prelabeled | reviewed | locked
    query_count  INTEGER NOT NULL,
    created_at   TEXT NOT NULL DEFAULT (datetime('now'))
);
```

#### `annotation_session_queries` — 批次 ↔ query 关联

```sql
CREATE TABLE annotation_session_queries (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id    TEXT NOT NULL,
    query_id      TEXT NOT NULL,
    label_status  TEXT NOT NULL DEFAULT 'selected',  -- selected | prelabeled | reviewed | finalized
    selected_at   TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE(session_id, query_id)
);
```

#### `eval_ground_truth` — 五档相关性标注（累进式）

```sql
CREATE TABLE eval_ground_truth (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    query_id      TEXT NOT NULL,         -- 对应 raw_queries.id
    corpus_id     TEXT NOT NULL,         -- 对应 eval_corpus.id（parent 级，非 chunk）
    relevance     INTEGER NOT NULL,      -- 0 ~ 4
    label_source  TEXT DEFAULT 'llm',    -- 'llm' | 'corrected'
    labeled_at    TEXT NOT NULL DEFAULT (datetime('now')),
    notes         TEXT,
    UNIQUE(query_id, corpus_id)
);
```
- ground_truth 的 `corpus_id` 始终指向 `eval_corpus.id`（parent 级），不论 chunk 与否

#### `eval_embedding_cache` — 向量缓存

```sql
CREATE TABLE eval_embedding_cache (
    source_type TEXT NOT NULL,           -- 'query' | 'corpus' | 'corpus_chunk'
    source_id   TEXT NOT NULL,           -- raw_queries.id / eval_corpus.id / eval_corpus_chunks.id
    model_name  TEXT NOT NULL,
    embedding   TEXT NOT NULL,           -- JSON float64 数组
    dimension   INTEGER NOT NULL,
    created_at  TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE(source_type, source_id, model_name)
);
```

#### `eval_metadata` — 元信息

```sql
CREATE TABLE eval_metadata (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

## 三、五档相关性标注标准

评测用 NDCG（归一化折损累计增益）做排名质量评估，需要分档权重。

| 档位 | 分数 | 标签 | 含义 | 示例（query: 我上个月吃饭花了多少） |
|------|------|------|------|------|
| **0** | 0 | `irrelevant` | 完全无关 | 「减肥计划」「股票涨了」 |
| **1** | 1 | `tangential` | 同话题但无帮助 | 「餐饮行业趋势」「做菜教程」 |
| **2** | 2 | `partial` | 弱相关，有线索但答题不够 | 「外卖比堂食贵」「最近胃口不好」 |
| **3** | 3 | `relevant` | 直接相关，回答可用 | 「5月食品支出概览」 |
| **4** | 4 | `perfect` | 完美命中，最优答案 | 「5月餐饮月度明细：¥2,847」 |

## 四、标注流程

### 4.1 整体流水线

```
MySQL 原始数据
    │
    ▼  [B1] ExportStrategy 实现：筛选 + 生成 query + 导出 corpus + 预灌 embedding
    │
raw_queries + eval_corpus [+ eval_corpus_chunks] + embedding_cache
    │
    ▼  [B2/B3] 建 annotation_session → LLM 打分 → 人工复核
    │
eval_ground_truth（累进）
    │
    ▼  [B4] 自洽率 ≥ 90% → 冻结 project
    │
    ▼  [B5] 评测引擎读取 eval.db → SearchEngine 跑检索 → 对比 ground_truth → 报告
```

### 4.2 增量构建

```
session_1: 选 10 条 → LLM 标注 → ground_truth 有 10 × M 行
session_2: 扩充到 50 → ground_truth 新增 40 × M 行
session_3: 扩充到 200 → ...
```

每批一个 `annotation_session`，标注结果累进式存入 `eval_ground_truth`。

## 五、MySQL 导出策略

### 5.1 queries 导出

取决于策略。`all-past-data` 直接取原始消息并过滤短消息。`with-history` 回查 MySQL 拼接历史。

### 5.2 corpus 导出

取决于策略：

**full-content 策略**：全量导入 notes + memories 到 `eval_corpus`，不创建 chunk。

**chunk 策略**：导入 notes + memories 到 `eval_corpus`（parent 级），同时按句切分写入 `eval_corpus_chunks`。embedding 缓存存 chunk 向量。

### 5.3 嵌入向量预灌

B1 导出时同步灌入 query 和 corpus 的 full-content/chunk 向量到 `eval_embedding_cache`。

## 六、Embedding 缓存策略

- B1 导出时预灌，后续零嵌入成本
- 评测引擎查缓存的 query 向量（B1 已灌），corpus 向量（B1 已灌）
- chunk 模式：搜 chunk 向量 → 按 `corpus_id` 去重 → 返回 parent
- 换嵌入模型时新向量首次花钱算，后续缓存命中

## 八、版本管理约定

- `dataset/projects/` 不为 git 管理（隐私数据在 `server/data/eval/`）
- `server/data/eval/` 本地独有，git 双保险忽略
- `eval_metadata` 记录版本号、标注人、自洽率

## 九、与评测引擎的关系

```
┌─────────────────────┐        ┌─────────────────────┐
│  dataset/projects/   │        │  server/internal/eval/│
│  (数据，冻结)          │  ←读取  │  (评测引擎，可运行)      │
│                     │        │                     │
│  eval.db            │        │  evaluator.go       │
│  ├── raw_queries    │        │  ├── 加载 query      │
│  ├── corpus         │        │  ├── SearchEngine    │
│  └── ground_truth   │        │  ├── 对比 ground_truth│
│  └── chunks         │        │  └── 输出指标        │
└─────────────────────┘        └─────────────────────┘
```

评测引擎只负责「怎么搜」，不负责「怎么切」「query 怎么来」。

## 十、总结

核心设计原则：

1. **ExportStrategy 决定一切**：query 文本和 corpus 形态在 project 创建时冻结
2. **子语料去重归父**：chunk 模式搜 chunk → 按 parent 去重 → 返回父级 corpus
3. **标注 > 评测三层清晰**：标什么就测什么，预处理前置，评测零负担
