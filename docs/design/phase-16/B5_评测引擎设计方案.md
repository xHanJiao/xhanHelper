# B5 评测引擎设计方案

> 2026-06-16 更新 · 离线试题集 Phase B5
>
> 习题集冻死后，评测引擎是独立消费者。核心设计：**前端创建评测任务 → 后端异步执行 → SearchEngine 可插拔 → 全量排名 + 单条 drill-down**。
>
> **2026-06-16 最新**：评测任务放前端管理。SearchEngine 返回全量结果不截断，指标按 K 分别算。前端展示汇总指标 + 任意 query 的完整排名（含分数、GT、差距）。

---

## 一、设计目标

| 目标 | 说明 |
|------|------|
| **前端驱动** | 评测任务在浏览器里创建、执行、查看，不用 CLI |
| **异步执行** | 后端 goroutine 跑检索 + 对比，前端轮询状态 |
| **全量排名** | SearchEngine 不截断 topK，每条 query 返回全部 corpus 排序结果 |
| **可钻取** | 从汇总指标点进单条 query，看完整排名 + 每个 corpus 的 score/GT/落差 |
| **可扩展** | 加新搜索方式只需实现 `SearchEngine` 接口 |

## 二、核心抽象：SearchEngine

```
eval.db（冻死）
  ├── raw_queries（query，ExportStrategy 产出）
  ├── eval_corpus（语料 parent 级）
  ├── eval_corpus_chunks（子语料，可选）
  ├── eval_embedding_cache（向量，B1 预灌）
  └── eval_ground_truth（5 档标注）
        │
        ▼
  SearchEngine (vector / keyword / hybrid)
        │
        ▼
  全量 corpus 排序结果 → 对比 ground_truth → NDCG / Recall / MRR
```

### 2.1 SearchEngine 接口

```go
type SearchEngine interface {
    Name() string
    Index(ctx context.Context, db *sql.DB) error
    // Search 返回全部 corpus 的排序结果，不截断 topK
    Search(ctx context.Context, db *sql.DB, query string) ([]SearchResult, error)
}

type SearchResult struct {
    CorpusID string  `json:"corpus_id"`
    Score    float64 `json:"score"`
}
```

| 实现 | 索引 | 搜索 | 依赖 |
|------|------|------|------|
| `VectorEngine` | 读 `eval_embedding_cache` 中 corpus/chunk 向量 → 内存 | query 向量 → cosine → 全量排序 | embedding API（仅 cache miss） |
| `KeywordEngine` | `eval_corpus` 文本 → SQLite FTS5 | FTS5 MATCH → 全量结果 | SQLite 内置 |
| `HybridEngineRRF` | 包 vector + keyword | RRF 合并两个引擎的全量结果 | VectorEngine + KeywordEngine |

### 2.2 chunk 模式

`VectorEngine` 检测 `eval_corpus_chunks` 非空时：

```
Index: 加载 chunk 向量（source_type='corpus_chunk'）
Search: query vs chunk → cosine → 按 corpus_id 去重（取最高分 chunk） → 返回 parent 排序
```

> `KeywordEngine` 和 `HybridEngine` 同理：索引建在 chunk 文本上，搜索结果按 parent 去重。

## 三、eval_runs 表

```sql
CREATE TABLE eval_runs (
    id           TEXT PRIMARY KEY,
    project_id   TEXT NOT NULL,
    name         TEXT NOT NULL,
    config       TEXT NOT NULL,          -- JSON: {engine:{type,model,...}}
    status       TEXT NOT NULL DEFAULT 'pending',  -- pending | running | done | error
    report       TEXT,                   -- JSON: 汇总指标
    detail       TEXT,                   -- JSON: 每条 query 的完整排名 + 指标
    error_msg    TEXT,
    created_at   TEXT NOT NULL DEFAULT (datetime('now')),
    started_at   TEXT,
    finished_at  TEXT
);
```

### report JSON（汇总）

```json
{
  "metrics": {
    "recall@5": 0.72, "recall@10": 0.85,
    "precision@5": 0.60, "precision@10": 0.42,
    "ndcg@5": 0.58, "ndcg@10": 0.61,
    "mrr": 0.45
  },
  "total_queries": 14,
  "total_corpus": 453,
  "config": {"engine": {"type": "vector", "model": "doubao-embedding-vision-251215"}}
}
```

### detail JSON（每条 query 的完整排名）

```json
{
  "query_id_001": {
    "query": "我上个月吃饭花了多少",
    "results": [
      {"rank": 0, "corpus_id": "abc", "score": 0.87, "gt": 4},
      {"rank": 1, "corpus_id": "def", "score": 0.74, "gt": 2},
      {"rank": 2, "corpus_id": "ghi", "score": 0.62, "gt": 0},
      {"rank": 452, "corpus_id": "zzz", "score": 0.01, "gt": 0}
    ],
    "metrics": {"reciprocal_rank": 1.0, "ndcg@5": 0.92, "ndcg@10": 0.78}
  }
}
```

> `gt` = ground_truth relevance（0~4）。corpus 内容不存 detail，前端需要时用 corpus_id 从 `eval_corpus` 表实时查。

## 四、5 档评分 ↔ 指标映射

| 指标 | 计算方式 |
|------|----------|
| **Recall@K** | topK 中 GT ≥ 3 的 corpus 数 / 总 GT ≥ 3 的 corpus 数 |
| **Precision@K** | topK 中 GT ≥ 3 的个数 / K |
| **NDCG@K** | Σ( (2^rel - 1) / log2(rank + 2) ) / ideal DCG<br>5 档权重：0→0, 1→1, 2→3, 3→7, 4→15<br>排名越靠前权重越高 |
| **MRR** | 1 / (第一个 GT ≥ 3 的位置 + 1) |

## 五、API 端点

全部挂 `/api/admin/eval/` 下，Auth + AdminOnly。

| 方法 | 路径 | 用途 |
|------|------|------|
| `GET` | `/api/admin/eval/projects/:project/runs` | 评测任务列表 |
| `POST` | `/api/admin/eval/projects/:project/runs` | 创建评测任务 |
| `POST` | `/api/admin/eval/projects/:project/runs/:id/execute` | 执行评测（异步） |
| `GET` | `/api/admin/eval/projects/:project/runs/:id` | 任务详情（含 report + 返回前 20 条 query 的 detail 摘要） |
| `GET` | `/api/admin/eval/projects/:project/runs/:id/queries/:qid` | 单条 query 完整排名 |

### 创建评测任务（POST /runs）

**请求**：
```json
{
  "name": "vector baseline",
  "config": {
    "engine": { "type": "vector", "model": "doubao-embedding-vision-251215" }
  }
}
```

**响应**：
```json
{ "status": "ok", "data": { "id": "run-001", "status": "pending" } }
```

### 执行评测（POST /runs/:id/execute）

立即返回 + 后台异步执行：

```json
{ "status": "ok", "data": { "status": "running" } }
```

前端轮询 `GET /runs/:id` 直到 `status=done`。

### 评测任务详情（GET /runs/:id）

```json
{
  "status": "ok",
  "data": {
    "id": "run-001",
    "name": "vector baseline",
    "status": "done",
    "config": { ... },
    "report": { "metrics": { ... }, "total_queries": 14 },
    "queries": [
      {
        "query_id": "xxx",
        "query": "我上个月吃饭花了多少",
        "summary": { "reciprocal_rank": 1.0, "ndcg@5": 0.92 },
        "top_results": [
          { "rank": 0, "corpus_id": "abc", "corpus_content": "5月餐饮...", "score": 0.87, "gt": 4 },
          { "rank": 1, "corpus_id": "def", "corpus_content": "外卖比堂食...", "score": 0.74, "gt": 2 }
        ]
      }
    ],
    "created_at": "...", "finished_at": "..."
  }
}
```

> `GET /runs/:id` 返回 `queries` 列表时，每条只带前 5 条 top_results 作预览。点进单条时调 `GET /runs/:id/queries/:qid` 返回完整 453 条排名。

### 单条 query 完整排名（GET /runs/:id/queries/:qid）

返回该 query 的全部 453 条 corpus 排序结果，每行带 rank/score/GT/corpus_content。前端做虚拟滚动或分页加载。

## 七、异步执行流程

```
前端 POST /runs/:id/execute
    │
    ▼
后端同步: INSERT eval_runs (status=pending) → 返回 {status: "pending"}
    │
    ▼
go func():
    status=running → UPDATE
    │
    evaluator.Run(runID):
    │   ├── SearchEngine.Index(db)
    │   ├── for each query in raw_queries（仅限有 ground_truth 的）:
    │   │   └── SearchEngine.Search(db, query.content) → 全量排名
    │   ├── 对比 ground_truth → 算指标（Recall@5/10, NDCG@5/10, MRR）
    │   ├── 写入 report JSON + detail JSON
    │   └── status=done → UPDATE
    
前端: setInterval 5s → GET /runs/:id → status=done → 渲染报告
```

## 九、嵌入成本

- query 向量：B1 导出时预灌，评测零成本
- corpus 向量：B1 导出时预灌，评测零成本
- 换嵌入模型：首次 run 时计算并写缓存，后续命中

## 十、总结

B5 评测引擎核心设计原则：

1. **前端驱动**：评测任务在浏览器里管理，不用 CLI
2. **异步执行**：goroutine 后台跑，前端轮询状态
3. **全量排名**：不截断 topK，每条 query 返回全部 corpus 排序
4. **可钻取**：汇总指标 → 单条 query → 完整 453 行排名
5. **可扩展**：加引擎只需实现 `SearchEngine` 接口
