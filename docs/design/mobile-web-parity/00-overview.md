# 移动端优先的 Web 体验对齐 · 总览

> 日期：2026-11-01
> 状态：范围与 UI 已定；M1 骨架 + M2a/M2c（输入框图片链路、计划/无痕）已落地，M2b/M3 待开发
> 位置：`docs/design/mobile-web-parity/`；预览在同目录 `mockup.html` 与 `mockups/`
> 目标：把 Web 前端做成「手机上的主客户端」，桌面可用即可
> 对照：macOS 客户端 `client/xHelper/xHelper/Shared`
> 预览：`mockups/01-shell.html`、`mockups/02-chat.html`、`mockups/03-content.html`

## 一、要解决什么

Web 前端功能不少，但和 macOS 客户端比，缺的是「成品感」和「手机可用性」：

- 消息里没有卡片，文档/灵阅只能靠文字；
- 模型写的 `xhanhelper://document/<id>` 点不动；
- 左栏塞着一堆不用的功能，会话历史还只对管理员可见；
- 不能发照片，历史里的 `image_ids` 也直接丢；
- 灵阅（HTML 产物）完全没有入口；
- 视觉是冷调 SaaS，和 macOS 的暖米/墨绿不是一套；
- 移动端只是「把桌面缩小」，没有安全区、键盘、底部导航。

## 二、已拍板的产品决策

| 决策 | 结论 |
|---|---|
| 手机主导航 | 底部 Tab：对话 / 灵阅 / 文档 / 我的 |
| 桌面布局 | **不做常驻右栏、不做多 tab、不做拖拽**；顶栏 + 聊天主区，功能走全屏路由页 |
| 会话切换 | 放顶栏下拉（搜索 / 置顶 / 归档 / 新建） |
| 视觉 | 全站换 macOS 暖米 + 墨绿 token，含深色 |
| 第一批 | M1 骨架与移动端 + M2 聊天/灵阅/图片，形成一个可上线版本 |
| 文档 | 阅读器 + 只读批注，放 M3；M2 先做最小阅读页让卡片能跳 |
| 管理后台 | 仅桌面端提供入口；手机访问给「请用桌面端打开」 |
| PWA | 基础版：manifest + 图标 + 主题色 + 全屏 meta；不做离线/推送 |
| 用户消息 | 气泡（浅色淡绿底），不用 macOS 纯文本 |
| 多卡 | 单卡 + 横条「＋N」，展开 8 秒后自动收起 |
| 手机「我的」 | 2 列功能格子 |
| 灵阅列表 | 单列大卡 |
| 手机输入区 | 常驻贴底，键盘弹起时 Tab 隐藏 |
| 文档布局 | 桌面左目录 + 右批注；手机正文 + 底部浮动条 |

## 三、信息架构

### 桌面（≥ 1100px）

```
┌────────────────────────────────────────────────────┐
│ 顶栏：会话下拉 · 新建 · 功能 · 主题 · 头像          │
├────────────────────────────────────────────────────┤
│                                                    │
│              聊天卡片（正文列 720–760）             │
│                                                    │
└────────────────────────────────────────────────────┘
```

- 「功能」是顶栏入口，点开一个轻量菜单；选中后进入全屏路由页。
- 管理后台保持现有全屏页，从「功能 → 管理」进入。
- 不做 macOS 的右栏 tab 池、不做 PiP。

### 手机（< 1100px）

```
┌──────────────────────────┐
│ 顶栏：会话下拉 · 新建     │
├──────────────────────────┤
│                          │
│ 聊天 / 灵阅 / 文档 / 我的 │
│                          │
├──────────────────────────┤
│ 输入区（安全区内）        │
├──────────────────────────┤
│ 对话  灵阅  文档  我的    │
└──────────────────────────┘
```

- 「我的」是功能聚合页：图片、账单、记忆、主题、智能体、设置、已归档会话。
- 管理后台入口不在手机出现。

## 四、设计 token

唯一来源：macOS `Assets.xcassets`。Web 用 CSS 变量落一份，Naive UI 同步覆盖。

| token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--app-accent` | `#2F7D63` | `#92C8B4` | 主按钮、链接、选中态 |
| `--accent-secondary` | `#41C9E2` | 同色 | 少量强调 |
| `--bg` | `#F7EEDD` | `#1C1C1E` | 窗口底 |
| `--bg-deep` | `#EFE2C8` | `#141416` | 底部/渐变深处 |
| `--text` | `#3B2E1F` | `#FFFFFF` | 正文 |
| `--user-text` | `#2A7F58` | `#90D4A8` | 用户消息 |
| `--input` | `#F2F7F3` | `#2C2E2D` | 输入框/引用卡底 |
| `--tool` | `#E8E4EF` | `#2E2B36` | 工具/校验 pill |
| `--border` | `text 12%` | `white 12%` | 描边 |
| `--card` | `white 6%` | `white 6%` | 卡片白霜 |

表面规则：

- 浅色用白霜提亮，深色用白阴影 + 白 0.5px 描边，不用黑阴影压深色。
- 卡片圆角 12，浮层 10–14，输入栏 20。
- 正文列宽 728（最大 760），行高 1.6。
- 过渡统一 0.2s easeInOut；只动 opacity/scale/背景。

## 五、批次

| 批次 | 内容 | 产物 |
|---|---|---|
| M1 | 双端 shell、视觉 token、移动端适配、会话下拉、PWA 基础 | 可用的新骨架 |

## 六、不做什么

- 浏览器多 tab / 书签 / 下载历史 / 本页资源
- PiP 浮动聊天、照片模糊底图、毛玻璃实时材质
- 多会话 tab 池（用浏览器标签页）
- 语音输入、任意文件附件（macOS 自己也没有）
- 照搬 macOS 的划线批注连线、虚拟列表
- 聊天里展开历史工具调用详情

## 七、验收口径

手机走完这条链路即算第一批完成：

**登录 → 会话下拉 → 聊天 → 发照片 → 收到灵阅卡 → 点开看 → 返回 → 点文档引用 → 打开文档 → 分享 → 添加到主屏再打开。**

桌面走同一条链路，内容页全屏，管理后台可用。

## 八、风险

1. iPhone Safari 键盘/安全区必须真机验，`100vh` 不够。
2. iPhone 相册 HEIC 后端不收，前端要转码；`createImageBitmap` 对 HEIC 的支持要真机确认。
3. 灵阅正文要带 token `fetch` 后塞 `srcdoc`，不能把接口 URL 直接给 iframe。
4. 私有图片不能直接 `<img src>`，要 `fetch` 成 blob URL。
5. M1 会改 `App.vue` 布局和所有页面的 `100vh`，回归面大，必须先做 shell 再加功能。
