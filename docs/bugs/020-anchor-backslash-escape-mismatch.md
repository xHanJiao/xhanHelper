# 转义星号段落无法划线 —— 服务端投影没解析反斜杠转义

## 问题表现

在含 Markdown 转义字符的文档里，**跨过转义行的选区保存后正文里画不出波浪线**；抽屉「全部」里记录在、不在「已失活」里，点它 toast「这条划线在当前正文里定位不到」。

复现文档：dev 沙箱的 `特殊字符测试文档`（`8b6106ae-65bb-430e-b54a-545174b7d2ad`）。库里 3 条批注，第 1 条正常，第 2/3 条画不出且 `quote_rewritten=1`（服务端走了 rung 3 夹逼、把 `quote` 改写了）。坏掉的两条都跨过了这一行：

```
- 转义星号：\*不该变成斜体\*
```

## 根因：`project()` 把转义反斜杠当正文留下

同一段正文，两侧投影结果不同：

| 侧 | `转义星号：\*不该变成斜体\*` 投影后 |
|---|---|
| 服务端 `project(src)` | `转义星号：\不该变成斜体\`（**留了反斜杠**） |
| 客户端 `fold(DOM)` | `转义星号：不该变成斜体`（marked 已把 `\*` 解析成字面 `*`，反斜杠不存在） |

`project()` 只丢 `mdInlineMarkers`（`* _ ` ~ | [ ]`），**没有解析反斜杠转义**：`\` 不是标记、被当正文留下。于是服务端 rung 1/2 双输 → 掉进 rung 3 夹逼 → 把带 `\` 的投影文本写回 `quote`；客户端拿这个 `quote` 去 DOM 里搜（DOM 没有 `\`）→ 永远找不到 → 画不出。

这是「投影两边不一致」这一类问题的**第三次**发作（前两次见 `015` / `019`）——这次是转义。

## 服务端投影的真实语义

共享投影 = `dumb-strip(CommonMark-resolve(source))`：

1. **先**按 CommonMark 成对解析反斜杠转义（`\X`，X 为 ASCII 标点 → X；反斜杠消失）
2. **再**无脑丢标记 / 折空白（客户端 `fold` 分不清字面与标记，所以服务端也必须「无脑」）

关键点：不能反过来「先不解析、只把 `\` 也当标记丢掉」——那样 `C:\Users`、行尾 `\` 这类字面反斜杠会被错误抹掉。

## 修复

`service/document_anchor.go`：

- 新增 `resolveEscapes(src) ([]rune, []int)`：成对解析转义，返回解析后的 rune 流 + 「解析后下标 → 源文下标」映射。
- 新增 `isASCIIPunct(r)`：CommonMark 可转义标点集（`!-/`、`:-@`、`[-\``、`{-~`）。
- `project()` 改为先在 `res` 上跑原逻辑、`push` 时用 `orig[i]` 映射回源文。丢标记/块标记/有序标记的判断全部落到**解析后**的流上，于是 `\*` → `*` → 被丢、`1\.` → `1.` → 行首有序标记被丢，与客户端一致。

**客户端不动**：`fold` 只作用于已解析的 DOM，若再加一遍转义解析会对 `\\` 双重解析、反而把字面反斜杠弄丢。

## 钉子

`document_anchor_test.go`：

- `TestProjectResolvesBackslashEscapes`：`\*…\*` → 无 `*`；`C:\Users\Test` 原样；行尾 `\` 保留；`\\` → `\`；`1\. foo` → `foo`；`\- item` → `item`。
- `TestLocateEscapedAsterisks`：源文含 `\*不该变成斜体\*` + 客户端投影后的 quote → 断言命中且 `Fuzzy == false`（不再掉 rung 3）。

两条都做过**变异验证**：把 `isASCIIPunct` 改成恒 `false`，两条立刻变红；恢复后全绿。

## 存量脏数据

已被写坏的记录（`quote` 里带 `\`）不会自愈：删掉重划即可；或下次正文被改写触发 `RelocateAll` 时由 rung 3 重算出正确 `quote` 自愈。

## 留给以后的

- **跨语言投影不变量仍没有测试守着**（`015` / `019` / 本条的根因都在这条上）。建议加共享 golden fixture（同一份 markdown + 期望投影文本），Go 单测与 `check-reader-html.sh` 各读一遍。属 follow-up。
