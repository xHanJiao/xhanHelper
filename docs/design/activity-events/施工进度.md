## 一、施工约定（2026-09-26 定，勿擅自改）

- **基线分支**：`main`（已取消 `local-main`）。功能分支从 `main` 切。
- **包名**：`internal/activity`（emit + 存储，内聚独立）；后续派生放 `internal/activity/derive`。
- **存储层**：GORM（`gorm.io/driver/sqlite`，已在 `go.mod`）；events.db 与主库**不共用连接**。
- **Review 预算**：每期 Go 净改动（含测试）≤ ~250 行（S≤120 / M 120–250）。超了就拆下一期。
- **采集开关**：`activity.enabled` **默认开**（config 里 `*bool`，nil = 开）；云端 `APP_ENV=prod` 必须在 `conf/config.prod.yaml` 显式 `false`。非 sqlite（MySQL/云端）一律不启用。
- **验收**：主链路相关期给"真机跑一次聊天"的观察点；纯后台期只要求 `go build ./... && go test ./...` 绿。每期做完**停下等用户 review**，不自动进下一期。
- **只 `git add` 本期路径**，禁止 `-A`。提交前须用户同意。
- **施工中改文档**：设计/契约有变，先改附表 A/B 或设计篇，再改代码；进度记在本文件。

  - `db.go`：`Open(path, enabled)` 用 GORM 开 sqlite、DSN 带 `journal_mode=WAL`/`synchronous=NORMAL`/`busy_timeout`、建表、`meta` 预置键、返回 `*Store`（内含 `*gorm.DB`；`GetMeta`/`SetMeta`/`Close`/`DB` 已就位）。`DBPath(mainDBPath)` 算同目录 `events.db`。
- `cmd/xhan-helper/main.go`：sqlite 且开关开 → 开 events.db，启动日志打一行生效值，defer 关闭。

**验收**

- `meta.activity.enabled` 仅在启用时写入（禁用时不建库、只在日志声明）。见约定「采集开关」。

### P2 · emit 入口 ✅（2026-09-26）

**做了什么**
- `internal/activity/emit.go`（新）：`Event`（调用方只填语义字段）+ `eventRow`（events 表行，可空列用指针→落 NULL）+ `Emitter`（唯一 emit 入口）。
  - 公共字段由 `build` 补：`event_id`（空→uuid）、`occurred_at`（零→now，ISO8601 毫秒带时区）、`received_at`（UTC）、`schema_version`、`actor` 默认 system、`trigger` 默认 manual；调用方非空值不覆盖。
  - 背压：内存有界队列（1024），满则**丢最旧** + `Dropped()` 计数，`Emit` 非阻塞。
  - 批量：1 秒或 100 条先到先刷；`insertEvents` 一批一事务，`OnConflict{DoNothing}` 同时兜 `event_id` 主键与 `(type,biz_key)` 部分唯一索引。
  - `Flush()` 供里程碑立即刷；`Close()` 停 emitter 并刷完。
  - **空 `biz_key` 落 NULL**——空串会撞部分唯一索引，把无业务键事件互相吞掉。
- `internal/activity/db.go`：`Store` 持 `em`；`Open` 起 emitter；`Store.Emit/Flush` 委托；`Close` 先停 emitter。

**验收**
- `go build ./... && go test ./...` 绿，`go vet ./internal/activity/...` 干净。
- 单测：公共字段补全、调用方值不被覆盖、`event_id` 幂等、`(type,biz_key)` 幂等、无业务键多条都留、attrs JSON、队列满丢最旧且非阻塞。

**实际体量**：Go 净增 ~480 行，**超 M**。拆开：双结构体字段声明 ~110 行、测试 183 行、真正的逻辑（队列+批量+build）~120 行。字段声明是"入口 vs 表行"两层契约的成本，未拆。

**留下的口子**
- 各事件 type 的落点在 P3+；`Store` 暴露到 agent 层已由 P3 完成（`OrchestratorConfig.Activity`）。

### P3 · turn 定义 + 穿参 ✅（2026-09-26）

**做了什么**
- `internal/activity/emit.go`：加事件 type 常量（`TypeChatTurnStarted/Ended`）与 outcome 常量（`OutcomeCompleted/Cancelled/Failed`）。
- `internal/agent/turn.go`（新）：`Turn` + `(o *Orchestrator) StartTurn(ctx, convID, trigger, parentEventID)` + `Turn.Finish(outcome)`。
  - 起止 event_id 在 StartTurn 时就预分配两端，故 `pair_id` 能真正**互指**；`biz_key = turn_id`；`actor=assistant`。
  - 采集关闭（`o.activity==nil`）→ `ID` 为空、全部 no-op（不生成 uuid、不发事件）。
  - `Finish` 用 `sync.Once` 幂等。
- `internal/agent/orchestrator.go`：`RunRequest.TurnID`；`OrchestratorConfig.Activity` + 字段；`reactState.outcome`；`runReActLoop` 开头 `StartTurn`、defer 定 outcome（`ctx.Err()!=nil`→cancelled，否则看 `state.outcome`）；三处错误点置 `failed`；`executeConcurrently`/`executeClientTool` 穿 `turnID`/`convID`。
- `internal/agent/client_tools.go`：`Call` 加 `convID,turnID` 形参，payload 加 `conversation_id`、`turn_id` 两键。
- subagent 继承：`tool.ExecuteContext.TurnID`、`tool.SubAgentRunOptions.TurnID`、`SubAgentExt.TurnConvID/TurnID`、`MiniReAct` 的 ec 与 `execClientTool` 全穿；`task.go` 透传 `ec.TurnID`；`cleanupSubAgentTabs` 用父会话+父 turn。
- 接线：`appinit.InitAgents(..., activityStore)`；`main.go` 保留 `activityStore` 传入。

**验收**
- `go build ./... && go test ./...` 绿。
- 单测（`agent/turn_test.go`）：started/ended 二事件齐全、`turn_id`/`conversation_id`/`biz_key` 正确、`pair_id` 互指、`Finish` 幂等、outcome=completed；采集关闭时空 id + no-op 不 panic。

**决策/留下的口子**
- `StartTurn` 保留 `ctx` 形参（对齐设计篇签名；当前未用）。
- trigger 在 `runReActLoop` 硬编码 `manual`；主动搭话调度器未实现，届时改从 `RunRequest` 传（未加字段，YAGNI）。
- `chat.turn.started/ended` 的 `parent_event_id` 暂为空（根）；**P4 落 `chat.message.sent` 后再挂**。
- `actor` 取 `assistant`（设计篇未明写 turn 的 actor；turn 是助手处理周期，故如此定；如需 user 改一处）。
