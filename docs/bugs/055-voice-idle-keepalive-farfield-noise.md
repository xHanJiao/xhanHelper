# 055 近场闸开着，远处噪声仍给语音会话无限续命（2026-11-09）

## 问题表现

开了「只响应近处的声音」（标准档）后，远处的声音不再提交成一轮对话，但**语音会话永远不收口**：

- 隔壁 CJ 一直说话、嗑瓜子、收拾桌子 → 30 秒空闲收口一直不触发，语音条一直停在「听」
- 表现上像「说完不结束监听」，实际是会话被持续续命

## 根因

近场闸只挡了「提交」（`sentence`），没挡「续命」（`voice`）：

1. 服务端只要 ASR 识别出非空文本就发 `voice`（`server/internal/controller/voice.go:275`）。
   嗑瓜子、收拾桌子的声音也会被识别成文本，所以远处噪声一样发。
2. 客户端收到 `voice` 就无条件刷新空闲计时器：
   - PWA：`useVoiceChat.js` 的 `lastActivity = Date.now()`
   - Swift：`VoiceChatService.swift` 的 `lastVoiceAt = Date()`
3. 于是远处噪声一直来 → 计时器一直刷新 → 30 秒空闲收口永远不触发。

`voice` 续命原本是为了「用户说话中途（还没判停）别把会话收掉」，但它分不清近处还是远处。

## 最终方案

给续命也加近场判定（`shouldKeepAlive`）：

```
收到 voice
  → 取最近 400ms 的未门控电平帧
  → 不足 2 帧 → 不续命
  → 中位数 >= 阈值 ? 续命 : 不续命
```

- **400ms 短窗**：`voice` 是 partial，开口后一小段就发，等不到提交闸的 2 秒窗
- **帧不足不续命**：播报期门控帧被排除后窗口为空；播报期本来有 `speaking` / `isSpeaking` 保护，不靠 `voice`
- **关闭档恒续命**：与加闸之前完全一致
- 提交闸与续命闸用同一套电平帧，只是窗口不同（2s vs 400ms）

## 验证

- `front-end/src/utils/nearFieldGate.test.js`：远场 0.006 不续命、近场 0.21 续命、门控帧排除、旧帧不续命
- `Tests/NearFieldGateCoreTests/`：同构 4 条
- 真机待确认：标准档下隔壁持续噪声，30–35 秒内自动收口
