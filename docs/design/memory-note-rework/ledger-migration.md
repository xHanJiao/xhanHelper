# 台账内容迁移（notes / memories → documents） — 设计文档

> 版本：v1｜日期：2026-09-22｜状态：设计定稿，待执行
>
> 上位：《记忆 / 笔记改造 · 设计文档》（`design.md`）§4.6
> 估算：数据迁移（agent 执行，不写代码）+ prompt 措辞改动（3 面 / 0 缝 / 1 次往返）· ~3–5h

## 1. 背景

「逐日流水」这类台账内容（睡眠打卡、饮酒、健身/运动、时间日志、生活记录）单条价值低、攒起来才有意义，正确介质是文档表格。但它们在 notes / memories 里各存了一份，且和已有文档重复：

- notes 存活 1010 条里疑似台账 **279 条**：睡眠 183、健身追踪 22、饮酒记录 19、生活记录 12、健康 10、运动记录 7、财务/预算/消费 15、时间日志 4。
- memories 里：`睡眠管理(96)`、`记账(16)+消费管理(11)+消费记录(10)+记账习惯(8)+日常记账(4)+记账管理(3)`、`饮酒管理(5)+戒酒管理(4)` 等。
- 而 `documents`（186 篇）**已经有**这些台账：`汽水摄入追踪日志`、`我的饮酒日记`、`2026-07/08月度财报`、`2026-09月度预算`、`月度财报SOP`、`房价预测回测台账`、`西安房价周报-W33/W34`。钱的实际条目在 `bills` 表（专门工具）。

目标：把 notes / memories 里的逐日流水归入文档、删掉原记录，并堵住今后的回流。

## 2. 范围：只搬「逐日流水」

| 搬 | 不搬 |
|---|---|
| 睡眠打卡（每天睡点/醒点/自评/起夜） | 长期结论/洞察（睡眠质量评分标准、咖啡因敏感、回睡能力） |
| 饮酒条目 | 饮酒的习惯性判断、戒酒策略 |
| 健身 / 运动条目 | 健身计划、目标 |
| 时间日志（时间线记录） | 对时间使用的反思结论 |
| 生活记录（采买/待客的流水条目） | 关系性、状态性的长期信息 |

**不做**：`bills` 表本身不动（已有专门表和工具）；`财务 / 预算 / 消费目标` 类 notes 大多是**口径/结论**（如「月总开销约 1.3–1.5 万」），不是流水，**保留**。

## 3. 拆分规则（关键，不能整类搬）

同一个 topic 内部是混的——「睡眠」183 条里既有逐日流水，也有长期结论。**逐条判断**：

- 是「某一天发生了什么/读数多少」→ 流水 → 进文档。
- 是「规律、判据、结论、标准」→ 保留（并归到收敛后的规范 topic 下）。

归属不明确的，倾向**保留**（宁可少搬，不可丢掉洞察）。

## 4. 目标文档

- 优先 **append 到已有文档**：饮酒 → 「我的饮酒日记」；汽水 → 「汽水摄入追踪日志」。
- 没有的**按类新建**（如「睡眠日志」「时间日志」），内容用 Markdown 表格，一行一条带日期。
- 一篇文档覆盖一个连续时段/一类流水即可，不追求一次性完美排版。

## 5. 执行步骤（agent 执行）

1. **备份**：`mysqldump` 全量一份（防手滑）。
2. **停服**：避免内存向量库与库不一致。
3. **归集**：逐 topic 读流水条目 → 写入/追加对应文档（document 工具或直接 DB）。
4. **删除原记录**：删 notes（`SoftDelete`）/ memories（硬删），并走 **bug `017` 要修的完整清理**（`embeddings` 行、`embedding_chunks` 行、内存向量）——若 `017` 先修好，直接用修好的删除入口；否则手工补清理。
5. **复核**：出数据库 diff（搬了多少、删了多少、文档新增/追加了哪些）+ 前后笔记/记忆条数。
6. **重启**：刷新内存向量库。
7. **抽查**：检索不再命中已搬的流水；保留的结论仍在。

> 前置依赖：**bug `017`（删除清理）先落地**，否则第 4 步会留一堆孤儿向量。

## 6. 防止回流：prompt 措辞改动

现有让 LLM 记笔记/提取记忆的表述里，要明确「逐日流水/台账禁止记入笔记与记忆，改用 document」。落点：

| 位置 | 改动 |
|---|---|
| `agent/promptbuilder/static.go:14`（准则 4，主记录规则） | 加一条：逐日流水（睡眠打卡、饮酒、运动、时间日志等台账）不记笔记，改走 document |
| `tool/note.go:62`（工具描述） | 同上，明确排除台账 |
| `tool/note.go:67-68`（目录 ShortDesc） | 同上 |
| `tool/note.go:111`（`record_note` 描述） | 同上 |
| `tool/document.go`（工具描述） | 点明「流水/台账/逐日读数归这里」 |
| `agent/extractor.go:47`（记忆提取 prompt 的 Task / OutputFormat） | 同一条排除（记忆侧同样产出了 `睡眠管理(96)`、`记账(52)`） |

## 7. 风险

1. **误搬洞察**：把长期结论当流水搬进文档并从记忆删掉 → 信息降级。规则是「不确定就保留」。
2. **删除残留**：依赖 `017`；未修完前执行会留孤儿向量。
3. **文档膨胀**：流水堆积使单篇文档过大 → 按类/按年切分，必要时只保留近段。
4. **不可逆**：备份 + dry-run 复核是唯一兜底。

## 8. 验收

- 搬前搬后条数对得上（搬走数 = 文档新增行数；删除数 = 减少条数）。
- 抽查 10 条已搬流水、10 条保留结论，人工确认归类正确。
- 检索层不再命中已搬流水。
