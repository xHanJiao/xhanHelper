# 074 · 网页输入框粘贴之后，拼音不再组词、数字落成圈码（①②③④）

- 日期：2026-11-21
- 平台：iOS Safari 与主屏 PWA 都命中（苹果自带拼音，九宫格）
- 相关：`docs/bugs/073`（同一个输入框的另一个坑：组合输入中丢拼音）

## 问题表现

在聊天输入框里粘贴一次（任意长度，两个字也行），**紧接着**打拼音：

- 拼音不组词，每一下击键直接插一个字符，中文完全上不去；
- 打数字时落进输入框的是圈码 `①②③④`（U+2460 段）而不是 `1234`；
- 切键盘的 `123` / 字母层、切输入法语言都不恢复；
- **切出页面再回来**（或等两三秒再打字）就正常。

不是必现，但粘贴后立刻打字时命中率很高。

## 根因

**iOS Safari 侧的问题，不是我们页面的代码。** 判断依据（全部真机验证）：

| 观察 | 说明 |
|---|---|
| 纯裸页 `<textarea>`（无 CSS、无 JS）也坏 | 跟我们的组件、样式、监听器无关 |
| 备忘录（原生输入框）不坏 | 只在「网页里的输入框」出现 |
| 别的网站（bing 搜索框）不坏 | 也不是「iOS 网页版通用」 |
| 真机上打出来的字符是 `⑧`（U+2467）等圈码 | 输入法走的是「击键 → 直接插一个字符」的降级路径，不是组词路径 |
| 事件时间线（`beforeinput insertText composing=false` + `input`，长度每次 +1） | 全程没有 `compositionstart/update`，即 IME 根本没进组词 |

也就是：**粘贴动作把 WebKit 与输入法的编辑会话打成了降级态**。降级态下键盘仍然连着输入框（英文还能正常打，这点也验证过），但输入法不能再组词，按键只能直接落字符。

同一份代码在 iOS/WebKit 内部到底是什么状态冲突，没有查到（需要 Safari 网页检查器抓 WebKit 侧日志，手机上不好抓）。所以这一条的定位停在「可稳定复现、且能靠重建编辑会话解除」。

## 方案（兜底，非根治）

`front-end/src/views/ChatView.vue`：粘贴落字之后**重写一次 textarea 的 value**，逼 WebKit 重建编辑会话。

- `resetEditorSession()`：记住光标和内部滚动位置 → `value=''` → `value=原文` → `setSelectionRange` 还原 → `scrollTop` 还原 → 重新量高；
- 两个入口都挂：`@paste`（光标操作栏粘贴）与 `@beforeinput`（`inputType === 'insertFromPaste'`，覆盖输入框上方「粘贴」提示），用一次 `setTimeout(0)` debounce 去重；
- 图片粘贴逻辑不变：带图片且不带文字的粘贴仍然走 `addImages`，不重建会话；
- 只对 iOS 生效（`useDevice().isIOS`）：桌面/安卓没有这个降级态，不值得白丢一次撤销栈。

**真机对比过 5 种做法，只有「重写 value」有效**，其余都无效：

| 做法 | 结果 |
|---|---|
| 什么都不做（对照） | 坏 |
| 粘贴后 `blur()` + `focus()` | 坏 |
| **粘贴后重写 value（保留光标）** | **有效** |
| 拦截 `paste` 自己 `execCommand('insertText')` | 坏 |
| 粘贴后只 `setSelectionRange` 一下 | 坏 |

## 已知代价

- **这次粘贴不能撤销了**：重写 value 会清掉撤销栈，⌘Z / 摇一摇撤不回刚粘贴的内容（后续输入仍可正常撤销到「粘贴后」的状态）。
- 理论上光标可能偏一格；本地 CDP 自检里光标、焦点、高度、后续输入都正常，真机也没观察到偏移。

## 验证

真机（2026-11-21，iOS PWA + Safari 标签页，苹果拼音九宫格）全部通过：

1. 光标操作栏粘贴 → 立刻打拼音：能组词上屏，不出现圈码。
2. 输入框上方「粘贴」提示粘贴 → 立刻打数字：落的是 `1234`。
3. 粘贴长文（4 行以上）：高度与内部滚动正常。
4. 粘贴后光标位置不变，键盘不被收起。
5. 粘贴后继续打字、Enter 发送正常。

本地（headless Chrome + CDP）：粘贴后 value / `selectionStart` / 高度 / `document.activeElement` 均未被破坏，后续输入与 v-model 一致，无报错。
