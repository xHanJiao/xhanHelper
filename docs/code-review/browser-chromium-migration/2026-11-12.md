## 已修（按轮次）

### P1（必修，已修）

| # | 问题 | 修法 |
|---|---|---|
| 1 | 只设 `root_cache_path` 不设 `cache_path` → CEF 进 incognito，cookie/localStorage 不落盘，等于把"换内核是为了登录态"的地基抽掉 | 两个路径都指向 `<数据根>/CEF` |
| 2 | `fetch-cef.sh --install` 的增量判定只比 framework 版本 → 改了 `helper_main.mm` 重编 stub 后仍"已是某版本，跳过安装"，app 里一直是旧 Helper（症状：改了完全没生效） | 增量判定 = framework 版本 + stub sha（戳文件 `.cef-helper-sha`，装完最后写） |

### P2（已修）

1. 窗口模式下调 `WasResized` / `WasHidden` / `NotifyScreenInfoChanged`——这三个是 OSR 专用（头文件原文 "only used when window rendering is disabled"），窗口模式里是空操作，留着会让人误判"黑帧问题已处理"。已删，文档 13.1 那条同步改口径。
2. `external_message_pump` 用固定 60Hz `NSTimer` 空转 → 改走 `CefBrowserProcessHandler::OnScheduleMessagePumpWork` 指导调度（合并排程、`delay<=0` 立即跑）。本 app 关窗驻留常开，这条是长期电耗。
3. `OnBeforeClose` 回调栈里把 `_client` 引用清零 → 经典"成员函数执行中 delete this"UAF 入口；改为只在视图 dealloc 时释放。
4. `createBrowserIfNeeded` 未就绪时静默 return 且标记卡死；`CreateBrowser` 失败不回滚 → 未就绪不置标记、失败复位并允许重试。
5. 加了 `CefKeyboardHandler` 想"把 ⌘ 键交回 AppKit" → **方向错了**：CEF 的 `return true` 语义是"我已处理"（事件不会回到 AppKit），会把网页里的 ⌘←/⌘C 一起吞掉。已整体撤除；app 快捷键本来由 `AppDelegate` 的局部 `NSEvent` monitor 在 `sendEvent:` 之前拿到。
6. `loadURLString` 在 `OnAfterCreated` 之前到来时会被静默丢弃 → 记进 `_pendingURL`，created 后补放。

### P3（已修的）

`ARCHS=arm64` 只加 mac target；修饰键判断不再被 Caps Lock/Shift 干扰；脚本两处 `|| true` 补理由；解包完整性改双判据（`include/` + framework Info.plist）；缺 `cmake`/`ninja` 给明确报错；文档 Helper 数量统一 ×5（含签名顺序方向）；14.4 进度行补齐。

# 代码审查：B3（四层伪装 + 回归探针）

> 范围：`CefDisguise.h`（新）、`helper_main.mm`（渲染进程挂 CefApp）、`CefBridge.mm/.h`（UA / `sec-ch-ua` / 探针回传 / `evaluateJavaScript`）、`CefSmokeWindow.swift` + `App.swift`（`--cef-probe`）、`scripts/cef-regression.sh`（新）、`fetch-cef.sh`（增量戳加头文件）
> 方式：构建前 review（避免浪费一次真机往返）。CEF 156 头文件逐个核过签名；helper 用同款 `clang++` 复跑编译链接通过。

**VERDICT: MINOR**。P0/P1 = 0；P2×4 + P3×3 全部已修。

## P2（已修）

1. **注入层静默降级**：整段 JS 包在一个 `catch (e) {}` 里，任何一层抛错都吞掉、后面几层直接不执行；异常不逃出 IIFE 所以 `Eval` 恒返回 true，155 行的失败日志成了死代码 → 改成**按层 try/catch**，每层 `console.error("[cef-disguise] …")`（非 `XHPROBE:` 前缀，会照常进 Console）。
2. **`context->Enter()` 失败无日志**：症状会是"页面正常、伪装全无" → 改为 `NSLog(@"[cef] 伪装注入：进入 V8 上下文失败…")` 后 return。
3. **探针在 CEF 起不来时卡死在模态框**：`runProbe` 复用 `show()`，而 `show()` 初始化失败会 `alert.runModal()`（等人点），无人值守时进程锁死、报告不落盘，20s 自超时排在模态之后永不到达 → `runProbe` 先自己 `XHCefRuntime.initialize(...)`，失败直接写 `{"error":"cef init failed"}` 退出。
4. **脚本与探针超时同长（20s）**：探针的 20s 从窗口起来才计，脚本几乎总是先放弃，冷启动/钥匙串授权会被误报成"缺 framework"→ 脚本等 30s。

## P3（已修）

1. 第 1 层 UA 的检查无法证明 `settings.user_agent` 生效（CEF 默认 UA 本就同形）→ 脚本里写明这条只证明"没更糟"，真正被服务端用于判定的是第 2 层。
2. `sec-ch-ua` 的 host 判断用前缀匹配（`http://localhost.evil.com` 也会命中）→ 改用 `CefParseURL` 取 scheme + host 精确比。
3. 设计文档写的是 `frame->ExecuteJavaScript`，代码实际是同步 `CefV8Context::Eval` → 文档（第三章表格 + B3 落地口径）同步改口径。
