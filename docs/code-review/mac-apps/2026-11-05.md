# macOS 客户端质量评估（2026-11-05）

审查对象：`client/xHelper/xHelper/Shared`（macOS/iOS 共享）+ `client/xHelper/xHelperMac`（macOS 入口、设置、本地后端）。iOS 目标长期未使用，只做顺带识别，不作为结论依据。

方法：核心链路全量阅读（SSE、APIClient、ChatViewModel、本地工具、MCP、本地后端、文档阅读器）+ 与服务端路由/事件/字段逐项对照；`swift test` 339 个用例全绿。未执行 `xcodebuild`（项目约定），真机渲染与运行时并发未实测。

## 总评

整体质量高于个人项目平均水平，防御性设计与踩坑注释到位。主要风险集中在两处 P1（自定义地址崩溃、文档 WebView 的内容信任边界）、若干两端契约缝隙，以及 4 个超大文件带来的可维护性问题。

| 维度 | 评分 | 说明 |
|---|---|---|
| 架构分层 | 7/10 | model / APIClient / VM / View 清楚，个别文件职责过载 |
| 错误处理 | 7/10 | 多数有 `LogBuffer`，少数 `try?` 静默；63 处 `print` 游离在诊断体系外 |
| 并发 | 7/10 | NSLock / actor / 代次守卫完整，但依赖手工纪律 |
| 安全 | 7/10 | 工具风险分级、敏感路径、shell 白名单扎实；阅读器 HTML 是缺口 |
| 后端契约 | 7.5/10 | client_tools 协议优秀；事件顺序与字段有漂移 |
| 可测试性 | 6.5/10 | 纯逻辑抽得干净；契约层零覆盖 |
| 可维护性 | 6/10 | 巨型文件 + 手工维护的快捷键表 |
| macOS 使用体验 | 7.5/10 | 窗口/材质/键盘处理讲究；可访问性几乎没做 |

## 做得好的地方（后端配合亮点）

- **client_tools 协议**：结果预算链（20 KB 注入预算 → 20000 字节下发 → 客户端分页 `result_read_more` → 256 KB 传输护栏）、15s 心跳、"审批耗时从服务端预算里扣掉"、过期副作用工具直接放弃（`ChatViewModel+ClientTools.swift`）。工具命名/冲突/50 上限两端校验一致。
- **本地模式护栏**：`<env>:<random>` token、`XHAN_LOCAL_TOKEN`、dev/prod 数据根与 Keychain 项分离、`fatalError` 防三处数据根名漂移、`/api/health` starting/ready 分级。
- **SSE 字节流解码**：按字节切行、非法 UTF-8 只替换不丢块（曾丢过 `client_tool_call`）。
- **旧流回调**：task 身份 + 代次守卫；停止时 `runCtx` 与服务端解耦；404 当作无痕会话已销毁。
- **工具风险模型**：`ToolRiskLevels` / `ToolConfirmPolicy` 集中且有单测；全信任模式仍拒绝未授权目录。
- **活动埋点**：500 条上限、水位应答、4xx 隔离、成对事件同批落盘，两端一致。

## P0 — Critical

无。

## P1 — High

### P1-1 自定义服务地址未校验 + `URL(string:)!` 强解包 → 首次请求崩溃

- 位置：`xHelperMac/App.swift`（`serverURL` TextField）、`Shared/Services/APIClient.swift`（13 处 `URL(string: "\(baseURL)\(path)")!`）、`Shared/Services/SSEClient.swift:32`、`Shared/Services/DeviceManager.swift`（login/register/logout/default conversation）。
- 表现：设置里填 `127.0.0.1:8080`（指向自建后端最自然的写法），`URL(string:)` 返回 nil → 启动 `verifyToken → getDefaultConversationInfo` 直接崩溃。`http://[bad` 同理。
- 修法：在 `LocalPaths` 对用户填写的服务地址做归一化（去空白/尾斜杠、缺 scheme 补 `http://`）；请求层全部改为 `guard let url else { throw }`，错误可见（不再崩）。
- 状态：**已修（见文末修复记录）**

### P1-2 文档正文 WebView 执行未清洗 HTML，bridge 对任意 http(s) 页面可达

- 位置：`Shared/Views/DocumentReaderView.swift`（`marked.parse` → `content.innerHTML`，JS 开启，无 CSP；`decidePolicyFor` 放行 http/https；`reader` script handler 暴露写剪贴板/打开文档/删批注）。
- 表现：文档正文可能来自 agent 抓取的网页（提示注入场景）。`<img onerror=…>` / `<iframe srcdoc>` 可执行 JS；用户点击正文中的外链后，任意网站继承同一个 bridge。
- 修法（分层防御）：① 每次构建 HTML 生成随机 nonce，CSP 用 `script-src 'nonce-…'`（阻断内联事件处理器与注入 script）；② `innerHTML` 后遍历 DOM，移除 `script/iframe/object/embed/link/meta/base/form`、`on*` 属性与 `javascript:` URL；③ http(s) 导航一律 cancel 并交给系统浏览器打开（仅放行同文档锚点）；④ `img-src` 只放行服务端图片源 + `data:` + `blob:`。
- 状态：**已修（见文末修复记录）**

## P2 — Medium

### P2-1 `tool_call` / `tool_result` 只能 FIFO 配对，混合轮次会错位

- 位置：`ChatViewModel.swift`（`pendingToolCalls.removeFirst()`）；`server/internal/agent/orchestrator.go`（服务端工具先发 `tool_call`，客户端工具在 `client_tools.go` 执行时才补发；`tool_result` 却按原始调用顺序发）。
- 影响：`[fs__read, web.search]` 这类轮次 pill 名字与结果错配；`pending.tool` 参与文档卡/产物卡判定，错配时卡片可能漏挂。
- 修法：`tool_result` payload 增加 `tool_call_id`，客户端按 id 配对、FIFO 仅降级。
- 状态：待办

### P2-2 SSE 事件表漂移且未知事件静默丢弃

- 位置：`SSEClient.swift`（缺 `plan_done` / `thought` 映射；`default: return` 无日志）；服务端 `controller/chat.go` 会发这些事件。
- 修法：补齐映射；未知事件打一次 warning；补一份两端共用的 event 名清单/测试。
- 状态：待办

### P2-3 `/api/chat` 请求字段漂移

- 位置：`SSEClient.swift` 发 `memory_threshold` / `memory_limit`，服务端只认 `memory` 对象；`ChatViewModel` 的 `cachedTemperature/...` 链最终发出的参数服务端不消费（后者为已文档化的有意忽略）。
- 修法：删除这两个字段与缓存链，或在服务端实现并登记。
- 状态：待办

### P2-4 四个超大文件，职责混杂

- `Tools/BrowserToolProvider.swift` 4,288 行；`Views/DocumentReaderView.swift` 1,798 行（约 1,200 行内嵌 HTML/CSS/JS）；`ViewModels/ChatViewModel.swift` 1,791 行 / 55 个 `@Published`；`xHelperMac/App.swift` 1,545 行（AppDelegate + App + 设置 + 登录 + 目录选择）。
- 修法：纯文件级拆分；阅读器模板落成 bundle 资源 `reader.html`。
- 状态：待办

### P2-5 契约层零单测

- 339 个测试全在纯逻辑；SSE 映射、`done` 解析、响应模型解码无覆盖，`Message`/`Conversation` 的死字段本可被 fixture 测试抓住。
- 修法：抽 `ChatWireCore` 纯逻辑 target，用真实服务端 JSON 做 fixture。
- 状态：待办

### P2-6 账单 CSV 导出不校验 HTTP 状态

- 位置：`APIClient.exportBillsCSV` 忽略 status 与响应体；`BrowsePanelView.exportCSV` 拿到字符串直接 `try?` 写盘。
- 影响：401/500 时把错误 JSON 写成 `bills.csv`，用户以为成功。
- 状态：待办

### P2-7 可访问性几乎为零

- 全仓 5 处 `accessibilityLabel`；大量纯图标按钮只有 `.help`（hover 不等于 VoiceOver 标签）。
- 修法：优先补 TopBar、输入栏、右栏 tab、工具确认条。
- 状态：待办

### P2-8 两处用户可见加载用 `try?` 静默吞错

- `ChatViewModel.loadPlanTodo`、`reloadSubagentMessages`：失败后 UI 停旧状态且无日志。
- 修法：就地 `LogBuffer`（有意降级）。
- 状态：待办

## P3 — Low

- `print` 与 `LogBuffer` 双轨（63 处 `print`；`[B-Type]` 还会把 agent 输入的文本打到 stdout）。
- `Message.reasoningContent/memoryIds/toolCallId`、`Conversation.lastExtracted*` 都是 `let … = nil`，合成 `Decodable` 永远解不出来（目前无人读，属误导性死代码）。
- tab 淘汰调用 `stopStreaming()`：会终止服务端 ReAct、`ShellProcessRegistry.killAll()` 全局杀本地 shell、悬挂待处理确认。
- 401 不自动刷新重试（只有会话列表识别 401；token 刷新是 1 小时定时器）。
- 服务端潜在雷：`emitDone` 用 `fmt.Sprintf` 拼 JSON；`WriteSSE` 不转义换行；`sendEvent` best-effort 可能丢 `done`，客户端无流结束兜底。
- `MCPServer` 的 `nonisolated(unsafe)` 状态（`state`/`toolsCache`）部分不加锁写，依赖 `MCPManager` actor 串行化。
- 本地备份恢复对用户选中的 tar.gz 直接 `tar -xzf`，未校验归档内路径。
- 快捷键表手工维护（`ShortcutGuideView` 自注 ponytail）。
- `GET /api/documents` 列表返回全文正文，列表页用不到。

### P1-1 修复记录

- `LocalPaths.serverURLOverride` 归一化：去首尾空白/尾斜杠，缺 scheme 时按主机补（回环 / 私网 / `.local` → `http://`，其余 → `https://`）；`127.0.0.1:8080` 不再产生 nil URL。解析不出 host 时原样返回，由请求层给出可见错误，不静默回退默认后端。
- `APIClient` / `DeviceManager` 去掉全部 `URL(string:)!`，改走 `requestURL(_:)`，失败抛「服务地址无效」；`SSEClient` 失败走 `onError`；`HistoryPanelView` 的历史条目 URL 也改为 `guard let`（持久化的坏数据不再崩）。
- 测试：`Tests/LocalBackendCoreTests/ServerURLNormalizeTests.swift`（5 条，含「归一化后能构造请求 URL」的回归用例）。

### P1-2 修复记录

- 阅读器 HTML 每次构建生成随机 nonce，CSP 收紧为 `default-src 'none'` + `script-src 'nonce-…'` + `img-src 'self' data: blob:`，注入的 `<script>` 与内联事件处理器无法执行；`style-src 'unsafe-inline'` 保留（模板自身样式与 `--fs` 需要）。
- `render()` 在 `innerHTML` 后执行 `harden(content)`：移除 `script/iframe/object/embed/link/meta/base/form`、所有 `on*` 属性与 `javascript:/vbscript:` 的 `href/src/srcset/xlink:href`。
- 导航收口：正文里的 http(s) 外链不再在阅读器内打开（`NSWorkspace` 交给系统浏览器），只放行同文档锚点；`about/mailto/tel` 维持原行为。`reader` bridge 不再随导航暴露给外部站点。
- 自查：`scripts/check-reader-html.sh` 增补 5 条注入用例（script / onerror / javascript: / iframe），172 条断言 PASS；`scripts/snapshot-reader.sh` 真引擎 WKWebView 跑通（选区、划线、目录、字号均正常，正文无丢字）。两个脚本的注入探针补了测试 nonce，`reader-template.py` 同步替换 nonce 并对 `</` 做与 `JSONEncoder` 一致的转义。
- 类型检查：`swiftc -typecheck`（macOS 26.3，`-default-isolation MainActor`）通过，仅既有 warning。

### 复审跟进（2026-11-05 第二轮）

- 复审-P2-1（地址补 scheme）：无 scheme 地址不再一律补 http —— 回环 / RFC1918 / `.local` 补 `http://`，其余补 `https://`；显式 `http://` 仍可用。落地在 `LocalPaths.isLocalOrPrivateHost`，测试覆盖私网/公网边界（含 `172.32.0.1`、`192.169.0.1`、`fckeditor.example.com` 不被误判）。
