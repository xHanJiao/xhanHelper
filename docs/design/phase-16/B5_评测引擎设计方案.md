# B5 评测引擎设计方案（草案）

> 2026-06-15 · 离线试题集 Phase B5
>
> 习题集冻死后，评测引擎是独立消费者。核心设计：**三层可插拔抽象 + YAML 配置驱动**，不同检索策略组合不改一行代码。

---

## 一、设计目标

| 目标 | 说明 |
|------|------|
| **配置驱动** | 比较 N 种策略 = N 条 YAML config，不改代码 |
| **可组合** | query 处理 × corpus 切分 × 搜索方式，三维正交任意组合 |
| **可扩展** | 每层加新能力只需实现对应接口 |
| **可追溯** | 评测配置和报告可存可 diff |

## 二、核心抽象：三层可插拔

```
raw_queries ──→ QueryProcessor ──→ 文本
                  (raw / +history / +rewrite)
                                       │
eval_corpus ──→ CorpusProcessor ──→ 文本
                  (full / sentence_chunk / fixed_window)
                                       │
                                ┌──────┘
                                ▼
                          SearchEngine
                  (vector / keyword / hybrid)
                                │
                                ▼
                          TopK Results
                                │
                    对比 ground_truth
                                │
                    Recall / NDCG / MRR
```

### 2.1 QueryProcessor

```go
type QueryProcessor interface {
    Name() string
    // raw_queries 记录 → 可检索的文本表示
    Process(ctx context.Context, q QueryRecord) ([]string, error)
}
```

| 实现 | 说明 | 依赖 |
|------|------|------|
| `raw` | 直接用 `content`，不做任何变化 | 无 |
| `with_history` | 通过 `source_msg_id` 回查 MySQL，取前 N 轮用户消息拼接 | MySQL 连接 |
| `llm_rewrite` | 调 LLM 把 query 改写为更适检索的表述 | LLM |

> 历史消息是**动态上下文**，不是 corpus 的一部分。`raw_queries.source_msg_id` 是回到 MySQL 查询历史的钥匙。

### 2.2 CorpusProcessor

```go
type CorpusProcessor interface {
    Name() string
    // eval_corpus 记录 → 可被检索的文本表示（可能返回多条，如 chunk 后）
    Process(ctx context.Context, c CorpusEntry) ([]string, error)
}
```

| 实现 | 说明 | 依赖 |
|------|------|------|
| `full_content` | 直接用 `content`，单条 corpus = 单条文本 | 无 |
| `sentence_chunks` | 按句号/问号/换行切分成多个句子 | 无 |
| `fixed_window` | 固定窗口滑动切分（如 256 字 + 32 字重叠） | 无 |
| `existing_chunks` | 读取 MySQL `embedding_chunks` 表里已有的分句 | MySQL 连接 |

### 2.3 SearchEngine

```go
type SearchEngine interface {
    Name() string
    // 一次性建索引（corpus 冻死，建一次供多次 Search）
    Index(ctx context.Context, entries []CorpusEntry) error
    // 搜索
    Search(ctx context.Context, query string, topK int) ([]SearchResult, error)
}

type SearchResult struct {
    CorpusID string
    Score    float64
}
```

| 实现 | 说明 | 依赖 |
|------|------|------|
| `VectorEngine` | embed → cosine 相似度 | embedding API |
| `KeywordEngine` | SQLite FTS5 全文索引 MATCH 查询 | SQLite 内置 |
| `HybridEngineRRF` | 包 vector + keyword，Reciprocal Rank Fusion 合并 | VectorEngine + KeywordEngine |
| `HybridEngineWS` | 包 vector + keyword，加权求和合并 | VectorEngine + KeywordEngine |

## 三、评测配置（YAML）

```yaml
# compare.yaml — 一次跑多个策略，不改代码
evaluations:
  - name: baseline
    query:
      type: raw
    corpus:
      type: full_content
    engine:
      type: vector
      model: doubao-embedding-vision-251215
    top_k: 10

  - name: with_3_history
    query:
      type: with_history
      rounds: 3
    corpus:
      type: full_content
    engine:
      type: vector
      model: doubao-embedding-vision-251215
    top_k: 10

  - name: chunk_sentence
    query:
      type: raw
    corpus:
      type: sentence_chunks
    engine:
      type: vector
      model: doubao-embedding-vision-251215
    top_k: 10

  - name: chunk_fixed_256
    query:
      type: raw
    corpus:
      type: fixed_window
      size: 256
      overlap: 32
    engine:
      type: vector
      model: doubao-embedding-vision-251215
    top_k: 10

  - name: keyword_only
    query:
      type: raw
    corpus:
      type: full_content
    engine:
      type: keyword
    top_k: 10

  - name: hybrid_rrf_with_history
    query:
      type: with_history
      rounds: 3
    corpus:
      type: sentence_chunks
    engine:
      type: hybrid_rrf
      vector:
        model: doubao-embedding-vision-251215
      fusion_k: 60
    top_k: 10
```

## 四、评测执行流程

```
加载 YAML config
    │
    ▼
for each evaluation in configs:
    │
    ├── QueryProcessor.Process(每条 query)
    ├── CorpusProcessor.Process(每条 corpus)
    ├── SearchEngine.Index(全部 corpus)
    │
    ├── for each query:
    │   ├── SearchEngine.Search(query, topK)
    │   └── 对比 ground_truth → 记入 PerQuery 结果
    │
    └── 汇总指标 → 写入 Report

输出对比报告
```

## 五、评测报告

### 单条 query 粒度的结果

```go
type QueryEvalResult struct {
    QueryID    string
    Query      string
    Retrieved  []SearchResult       // 检索返回的 top K
    GTRelevant []string             // ground_truth 中 relevance ≥ 3 的 corpus ID
    Metrics    struct {
        ReciprocalRank float64      // 第一个相关结果的排名倒数
        NDCGAt5        float64
        RelevanceAt5   []int        // top 5 的实际相关度
    }
}
```

### 汇总指标

```go
type MetricsSummary struct {
    RecallAt5    float64
    RecallAt10   float64
    PrecisionAt5 float64
    PrecisionAt10 float64
    NDCGAt5      float64
    NDCGAt10     float64
    MRR          float64
}
```

## 六、嵌入成本

评测引擎查 `eval_embedding_cache`：

- 命中 → 直接用，零成本
- 未命中（换模型、换 corpus processor 导致新文本） → 调 API 计算 → 写缓存
- 同策略再跑时全部命中，不花钱

## 七、与 B1/B2 的关系

```
B1: 导出冻死数据 → raw_queries + corpus + embedding_cache
B2: 标注 → ground_truth
B3: 人工复核 → ground_truth 修正
B4: 质检锁定 → 项目 frozen
     │
     ▼
B5: 评测引擎 ← 读取 frozen 项目
     │
     ├─ YAML config 定义策略
     ├─ QueryProcessor + CorpusProcessor + SearchEngine 组合
     └─ 跑检索 → 对比 ground_truth → 输出报告
```

评测引擎完全独立于 B1-B4，只消费冻死的习题集，不修改它。

## 九、总结

评测引擎核心设计原则：

1. **配置驱动**：策略 ≠ 代码，策略 = YAML config
2. **三维正交**：QueryProcessor × CorpusProcessor × SearchEngine，任意组合
3. **可插拔**：三层各有接口，加能力 = 加实现，不碰已有代码
4. **只读消费**：不修改冻死习题集，只产出报告
