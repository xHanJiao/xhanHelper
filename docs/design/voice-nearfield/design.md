# 近场电平闸（只响应近处的声音）设计

> 状态：**已实现**（待真机校准播报期打断地板）
> 关联：`docs/design/voiceprint/design.md`（声纹方案，结论暂不实现）、`docs/research/voiceprint-probe.md`、`docs/design/voice-chat/design.md`
> 采集工具：`docs/design/voice-nearfield/level-sweep.html`（浏览器手动打标签，推荐）、`client/xHelper/scripts/voice-level-sweep.swift`（Mac CLI）

## 估算

- 5 面：PWA 采集+过滤、PWA 设置页、Swift 采集+过滤、Swift 设置页、两端提示
- 2 缝：播报期 AGC 未标定、两个 `@main` 入口都要挂设置
- 2 次真机往返：过滤验证、打断地板校准
- 1 个待拍决定：无（已定：两个闸一起做）
- **6–9 小时**

## 要解决的问题

连续语音对话里，麦克风会捡到远处的说话声：

- 2026-11-09 实测场景（两个都要治）：
  1. 人在客厅用语音，CJ 在另一个房间开电话会议（外放），麦克风把**会议里其他人的声音**
     识别成用户输入，变成一轮对话 → **提交闸**。
  2. 正在听回复时，CJ 那边一出声，**朗读被停掉**（macOS 自动打断只看音量：
     `VoiceChatService.swift:273-296`，连续 3 帧约 200ms 超过本底 2.2 倍）→ **打断闸**。

两个是连着的：打断通过后会 `flushPreroll` 把门控期的音频冲给 ASR，CJ 后半句话会被识别成
`sentence` 再提交一轮。只做提交闸的话，朗读还是会被停掉。

声纹能解决"身份"，但和打断存在时间尺度冲突（打断 200ms 内必须决定，豆包声纹约 1 秒才有结果），
完整落地 5–7 天。**电平闸解决的是"距离"，成本低一个量级。**

## 实测数据

口径与 App 一致：`level = min(1, RMS × 4)`，100ms 一帧。
「2s窗 p50」= 每 20 帧取中位数（模拟一句话的长度），是闸门真正要用的量（不是瞬时峰值）。

### iPhone（PWA 默认采集，`getUserMedia({audio:{channelCount:1}})`，AEC 开）

2026-11-09，门**开着**、人站在门口、会议在隔壁房间外放：

| 场景 | 2s窗 p50 中位 | p90 | 最高 |
|---|---|---|---|
| 静 | 0.003 | 0.003 | 0.004 |
| **远场会议（门开、站门口）** | **0.006** | 0.010 | **0.020** |
| 本人 50cm | 0.212 | 0.342 | 0.390 |
| 本人 20cm | 0.232 | 0.309 | 0.377 |
| 本人贴嘴 | 0.249 | 0.340 | 0.350 |

- **远场 0.006 vs 近场 0.21，差 35 倍**；阈值 0.05 时远场最高 0.020（低 2.5 倍）、近场高 4.2 倍。
- 20cm / 50cm / 贴嘴 三者电平几乎一样（0.21–0.25），说明 iOS 的音频处理把近场电平归一化了
  （`agc` 字段 iOS Safari 不上报，无法直接确认，但从这个趋同看基本可以认为开着）。
  这不影响闸门——闸门只区分"近场 / 远场"，不需要区分距离。

### Mac 内置麦（全关浏览器音频处理）

| 场景 | 1s窗 p50 中位 / p90 | 说明 |
|---|---|---|
| 静 | 0.006 / 0.019 | max 0.55 是摸麦克风的离群值 |
| 远场会议（关门隔墙，43s） | 0.006 / 0.011 | 与静场无差别；含走动 |
| 本人 50cm | 0.108 / 0.166 | |
| 本人 20cm | 0.163 / 0.195 | 只比 50cm 高 1.6 倍（4dB） |
| 本人贴嘴 | 0.516 / 0.640 | RMS×4 削顶，最高 0.96 |

### 结论

1. **电平闸够用**：iPhone 实测远场/近场差 35 倍（门开着也一样），阈值 0.05 有 2.5 倍以上余量。
2. **20cm 和 50cm 分不开**（Mac 1.6 倍、iPhone 几乎相同），也不需要有区别。
3. **摸麦克风/走动挡不住**：物理接触噪声 1s窗 p50 能到 0.15，会过闸。
4. 贴嘴说话会削顶到 1.0，对判定无影响（远高于阈值）。

> 早期版本写过"门开着挡不住（远场 p50 = 0.051）"，那个 0.051 是从一次未打标签的采集里猜的段落，
> 回看那段其实是本人说话的声音，归因错误。用带标签的 iPhone 采集重测后，门开场景同样挡得住。

## 方案

### 共同基础：带门控标记的电平历史

客户端本来就在算 `level = min(1, RMS × 4)`。新增一个约 2 秒的环形缓冲，每帧记 `(时间, 电平, 是否门控)`。

**为什么要记「是否门控」**：播报期间麦克风被门控（音频塞进 preroll、给 ASR 发等长静音保活），
但 `onLevel` 照样在跑，读到的是 **TTS 经 AEC 后的残留漏音**（`VoiceAudioEngine.swift:295-305`）。
外放大时残留能到 0.05–0.1，正好和阈值同量级，混进来会误判成"近场"。播完还有 600ms 尾音门
（`finishSpeaking`）同样算残留。所以：

| 闸门 | 用哪些帧 | 为什么 |
|---|---|---|
| 提交闸 | **只用未门控帧** | 它判的是"用户说的话有多响"，播报残留是噪声 |
| 打断闸 | 只能用门控帧 | 它就是在播报期间判的，没有别的帧可用 |

### 闸门 1：提交闸（解决"别人的话变成一轮"）

客户端收到 `sentence` 时，取这句话对应音频的**未门控帧（剔掉静音帧后）中位数**，低于阈值就丢弃。

```
sentence 到达（判停后 0.2–1s）
  → 取最近约 2 秒内「未门控」的 level 序列
  → 未门控帧覆盖不足 0.8 秒（或不足 4 帧）→ 放行（fail-open）
  → 按本窗 p20 估噪声本底：floor = min(cap, max(0.004, p20 × 2))，cap = min(0.04, 阈值/2)
  → 剔掉静音帧后：有声帧不足 2 帧 / 覆盖不足 0.15 秒 → 丢弃（没人靠近说，或只是碰了一下麦克风）
  → 有声帧中位数 >= 阈值 ? 提交 : 丢弃 + 轻提示
```

- **必须先剔静音帧再取中位数**：`sentence` 是判停（约 0.8s）之后才下发的，窗口尾部必然
  拖着一截静音。用真机数据模拟「1.2s 说话 + 0.8s 静音」的窗口，纯中位数只有 21–28% 能过闸
  （短句必被吞）；剔掉静音帧后近场 97–100% 通过、远场 0–1% 误收。静音帧不携带距离信息，
  剔掉它不影响判定，只是让"有声的那部分"说话。
- **阈值 0.05**（有声帧中位数）：iPhone 远场最高 0.020（低 2.5 倍），50cm 0.212（高 4.2 倍）
- **尖峰不算话**：剔掉静音后还要求有声帧覆盖 ≥0.15 秒，单帧碰麦尖峰（0.3~0.55）过不了闸
- **cap 跟着阈值走**（`阈值/2`）：否则「宽松」档（0.02）下连续 0.02–0.04 的人声会被本底剔光
- **数据不足时放行**：误拒比误收难受得多，宁可漏拦也别吞掉用户自己的话
- 纯客户端，不动服务端、不动 ASR 会话
- 代价：音频照样传豆包、照样计费，只是不提交

### 闸门 2：打断闸（解决"CJ 停朗读"）

现在的判定：连续 3 帧（约 200ms）超过 `max(0.03, 本底 × 2.2)` 就停朗读
（`VoiceChatService.swift:273-296`）。改成：

```
连续 5 帧（约 330ms）超过 max(0.06, 本底 × 4) 才打断
```

**只作用于 macOS / iOS**：PWA 没有自动打断（浏览器 AEC 不可靠，现状就是手动打断），不涉及这一闸。

- **必须相对本底为主**：本底（`residualBaseline`，门控期电平的 p20）本身就是"这一轮播报的残留有多响"，
  用倍数比较才不会被外放音量带跑；绝对地板 0.06 只是兜住"本底极低"的情况
- 播报期间 iOS 会切到 `.voiceChat` 模式拿 AEC 回声参考（`VoiceChatService.swift:685`），
  该模式带 AGC，安静房间会把增益调大 → 绝对阈值会漂，这就是必须用倍数的原因
- **顺带的好处**：打断被挡住时麦克风一直门控着，CJ 那段话根本不会进 ASR（门控期发的是静音），
  所以两个问题一起消失
- **已知挡不住**：摸麦克风的接触噪声（0.15–0.3 持续几百毫秒）照样会触发打断。
  要彻底解决只能走"先压低音量 → 验声纹 → 再决定停不停"（`voiceprint/design.md` 的 C1/C2）

### 闸门 3：续命闸（解决"远处噪声让会话永不收口"）

空闲收口（30 秒没人说话就结束会话）靠服务端的 `voice` 事件续命。`voice` 的触发条件是
「ASR 识别出非空文本」，**隔壁嗑瓜子、收拾桌子的声音也会被识别成文本**，于是远处噪声一直
刷新空闲计时器，会话永远不收口（`docs/bugs/055`）。

```
收到 voice（ASR 听到人声）
  → 取最近 400ms 的「未门控」电平帧
  → 不足 2 帧 → 不续命
  → 中位数 >= 阈值 ? 续命 : 不续命
```

- **用 400ms 短窗**：`voice` 是 partial，开口后一小段就发，等不到提交闸的 2 秒窗
- **帧不足不续命**：播报期门控帧被排除后窗口为空，而播报期本来就有 `speaking` 保护，不需要靠 `voice`
- **关闭档恒续命**：与加闸之前完全一致
- 提交闸（闸门 1）管「远处的话不变成一轮」，续命闸管「远处的话不拖着会话不收口」，两者帧集相同、窗口不同

### 分档

| 输入 | 策略 |
|---|---|
| iPhone/iPad 内置麦 | 标准档：阈值 0.05（实测已标定） |
| Mac 内置麦 | 标准档：阈值 0.05（实测已标定） |
| AirPods / 蓝牙耳机 | 宽松档：耳机麦本来就在嘴边，不需要高门槛（未实测） |

阈值 **0.05 全设备通用**，实测 Mac 与 iPhone 分离度都在 15–35 倍，不需要分设备档。
设置页给四选一「只响应近处的声音」：关闭 / 宽松（0.02）/ 标准（0.05）/ 近场（0.10），默认**标准**。不做自动校准。
关闭时提交闸不过滤、打断闸也用加闸之前的 0.03 / 2.2 倍 / 3 帧，与现状完全一致。

### 被忽略时的反馈

语音条上轻提示「已忽略：声音来自远处」，**限频 10 秒一次**。

必须有：没有提示的话，换个房间说话突然没反应会以为助手坏了。误拒是这个功能最容易踩的坑。

## 风险

- **摸麦克风/桌面碰撞**：单帧/双帧尖峰已被提交闸挡掉；持续 4–5 帧（≈200ms）的接触噪声爆发仍会过闸
  （打断闸也缓解不了）。要彻底挡住只能把「有声帧覆盖」提到 0.3 秒，代价是 0.3 秒以内的短句被吞
- **别人拿你的手机说话**：距离一样，过闸（这是声纹才能解决的）
- **播报期未标定**：TTS 在念时 iOS 切 `.voiceChat`（AEC + AGC），绝对电平会漂，
  打断闸的阈值必须真机另标一次
- **TTS 漏音污染电平**：播报期间电平读到的是 AEC 后的残留，外放大时能到 0.05–0.1，
  和阈值同量级；已用"提交闸只看未门控帧"规避，但残留多大没有实测数据
- **耳机未测**：AirPods / 蓝牙麦的电平特性和内置麦不同，耳机用户建议手动切宽松档，没实测过
- **不省 ASR 费用**：音频照传，只是不提交
- **可用性**：你离麦 1 米外说话会被拒；需要「灵敏度」档位和误拒提示

**估时**：6–9 小时 + 2 次真机往返

- 第 1 次真机：你自己说一句 → 正常回复；让 CJ 在另一房间说话 → 不提交 + 轻提示
- 第 2 次真机：AI 念长段的同时让 CJ 说话 → 看日志里的电平，校准打断地板

**验收标准**

1. 关闭开关 = 与现状完全一致（请求里不带任何新参数、不过滤）
2. 开启标准档：你说的话 100% 通过；隔壁会议声 0 提交
3. 灵敏度切「近场」：你 50cm 说话被拒（证明阈值真的在起作用，不是恰好没触发）
4. 播报中 CJ 说话不再停朗读（真机校准后）
5. 标准档下隔壁持续噪声（说话/嗑瓜子/收拾桌子）：30–35 秒内自动收口，不再无限续命
