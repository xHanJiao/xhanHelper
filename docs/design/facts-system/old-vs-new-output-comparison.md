## 1. 汇总对比

| 维度 | 新 facts | 旧 记忆 / 笔记 |
|---|---|---|
| 组织单位 | 原子 content，彼此独立 | memory topic（分组键）/ note（日期+tags） |

| 去重 | content hash + 向量 0.95 门槛 | topic 键 + 相似度合并 |

## 4. 结论

1. **问题不在「粒度小」，在「丢了组织层」。** 旧记忆的 `user_memories.facts` 本身就是原子事实数组，与新 facts 内容高度重叠；差别是它外面套了 **topic**——那正是注入单位。新系统把同一批原子拍平成独立行，`subject` 又 11/14 是「本人」、无法承担分组，于是散碎。相比旧系统，组织能力是**退化**。

2. **抽取器分不清「用户画像」与「工作台上下文」。** 这轮全是自举开发会话，最差场景。把「会话任务指令」（#2/#10/#13）、「环境工件态」（#8/#11）、「临时状态」（#3）都抽成了用户长期事实。

3. **钱账没按 design §5.2 路由。** 提示词的 DO NOT 里没有「钱账」这条，导致 #4/#6 与 bills 重复。

4. **去重靠 hash + 0.95 门槛 + 决策段，对"同一断言位、措辞不同"不稳。** #1/#5/#12 同 session 内都没合并。

5. **旧系统并非没问题**：无真正修订机制、topic 已涨到 163 个失控、同样记流水（睡眠、臭豆腐 25.2 元）。这些正是新系统要修的——但新系统在修这些问题时，**把旧系统顺手解决的聚合问题一起丢了**。
