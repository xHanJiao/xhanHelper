# 浏览器 Agent 工作区 + 人工验证手递手 真机验收指南

> 分支：`feat/browser-agent-workspace`
> 适用：浏览器 agent 标签工作区隔离 + 验证码/登录墙手递手 + 用户标签授权 + GC
> 说明：本批改动几乎全在客户端（Swift），服务端仅 `subagent.go` prompt 一处。**客户端由用户在 Xcode 编译运行**，agent 不执行 xcodebuild。

## 一、执行前准备

1. **编译**：Xcode 编译运行 xHelperMac（先 `git checkout feat/browser-agent-workspace`）。
2. **服务端**：`cd server && make dev`。
3. **客户端**：macOS App 登录进入对话。
4. **信任模式关闭**（否则 L3 确认条被跳过，授权用例测不到）。
5. 全程观察三个地方：右侧边栏（标签条 + 底部"Agent 工作区"条）、聊天区底部 AskUserBar、工具确认条。

## 二、验收方式

用聊天自然语言驱动 agent 操作浏览器，观察标签归属与确认流程。核心两条线：

- **Agent 侧**：让 agent 用 `browser` 工具连开多个页面（调研场景）
- **用户侧**：用户自己打开页面浏览，再让 agent 操作它

## 三、测试用例

### 1. Agent 工作区（核心）

| # | 操作 | 预期 |
|---|------|------|
| 1 | 对话："用浏览器打开 https://news.ycombinator.com 和 https://github.com/trending，各自简单介绍下内容" | 所有标签进主栏底部 **Agent 工作区** 条（展开显示 N 个），主栏标签条不闪、用户当前浏览不被打断 |
| 2 | 观察工作区条 | 折叠态显示 `Agent 工作区 N`；展开显示 favicon + 标题；空则整条消失 |
| 3 | 点击工作区某个标签 | 翻牌进主栏并激活显示该页（`promoteAgentTab`） |
| 4 | 继续让 agent 操作刚翻牌的页面（"再看下那个页面"） | agent 仍能读写该标签（owner 保留，按 agent 标签对待） |
| 5 | 在主栏关闭该翻牌标签（X / Cmd+W） | 正常关闭，工作区条同步移除 |

### 2. 沙箱：用户页面不被误操作

| # | 操作 | 预期 |
|---|------|------|
| 6 | 用户自己打开 2-3 个页面浏览，同时让 agent 并行开多页调研 | 用户标签条纹丝不动，agent 标签全在工作区；agent 读/写命中自己的标签 |
| 7 | 观察工具调用：agent 写工具缺 `tabId` | 报错"写操作必须指定 tabId"（不会落到用户激活页） |
| 8 | agent 调 `switch_tab` | 只改 agent 自己的激活指针，用户视图不切 |
| 9 | agent 调 `close`（关全部） | 只关自己的标签，用户标签全保留（修复前会清空用户标签） |
| 10 | agent `open` 带 `background:false` | 标签升主栏并激活（用户明确要求前台打开） |

### 3. 用户标签授权（grant）

| # | 操作 | 预期 |
|---|------|------|
| 11 | 用户自己打开某页（如一个表单页），说"帮我操作我打开的 XX 页，点一下里面的 XX" | 首次**写**操作弹确认条，标注"⚠ 作用于你自己的标签页"；点允许 → 执行成功 |
| 12 | 同一任务继续操作该用户标签 | 不再弹确认（owner 任务级缓存） |
| 13 | 拒绝确认 | 不执行，LLM 收到"用户拒绝"并说明 |
| 14 | 新开一个会话/新任务再操作用户标签 | 重新弹确认（owner 变了） |
| 15 | 只读用户标签（snapshot / read / get_text / get_value） | 直接放行，不弹确认 |

### 4. 手递手：验证码/登录墙（重点）

| # | 操作 | 预期 |
|---|------|------|
| 16 | 让 agent 打开一个带**真实登录/验证码**的站（见下方测试站点建议） | ① 页面自动升主栏并激活（⚠ 角标）② AskUserBar 出现 [前往处理] ③ agent 收到 `needsUserIntervention:true` 并调 `ui__ask_user` 说明原因 |
| 17 | 点 [前往处理] | 切到该页面 |
| 18 | 用户手动完成验证，回聊天点"完成" | agent 继续；该标签交还工作区条，⚠ 清除 |
| 19 | 改点"跳过" | agent 换源（重新 open 其他站点），标签交还 |
| 20 | 让 agent 打开 Cloudflare 防护站（被 CF 拦）或 403 站 | 硬失败"换源"，**不**弹手递手 |

**测试站点建议**（任选真实站点，人工试即可）：
- 密码框信号：任意需登录的页面（搜索"xxx 登录"）
- 验证码 iframe 信号：带滑动/图形验证码的站
- 兜底信号：标题/URL 含 `login`/`captcha`/`verify` 的站

### 5. GC 与清场

| # | 操作 | 预期 |
|---|------|------|
| 21 | agent 打开标签后停下不再活动，等 600s+ | 空闲 agent 标签自动关闭（可临时把 `cleanupIdleAgentTabs` 的 TTL 调小如 10s 快速验证，测完改回） |
| 22 | 手递手中等超 600s | 手递手标签**不**回收（`pendingHandoff` 豁免） |
| 23 | 子任务结束（完成/取消） | 服务端 `close_tab` 清场，agent 标签（含被翻牌的）全关 |
| 24 | 翻牌进主栏的标签 | 不参与 GC（`isAgentTab=false`，走正常标签生命周期） |

### 6. 回归

| # | 操作 | 预期 |
|---|------|------|
| 25 | 用户正常浏览：开/关/切换/下载/全屏 | 行为与改前一致 |
| 26 | 用户页面点 `target=_blank` / noopener 链接 | 正常开新标签 |
| 27 | agent 页面弹窗（target=_blank / noopener / 新窗口） | 进工作区，不切用户视图 |
| 28 | 服务端 | `cd server && go build ./... && go test ./...` 全绿 |

## 五、排查

| 现象 | 排查 |
|------|------|
| 工作区条不出现 | 确认开页的 agent 走的是 `browser` 工具且会话 owner 为 `subagent:*`；重启 App |
| agent 开了页但主栏闪切 | 该 open 是否带 `background:false`（前台打开=升主栏属预期）；否则查 `isAgentTab` 是否被错误置 false |
| 确认条没有"你自己的标签页"文案 | `needsUserTabGrant` 未命中：检查 `owner` 是否传空、目标标签 `session.owner` 是否为 nil |
| 手递手不触发 | 站点无密码框/验证码 iframe 且标题/URL 无关键词（信号弱）；或标题被 `isBlockedPageTitle` 判定为 bot 墙走了硬失败 |
| Cloudflare 也弹手递手 | wallProbe 兜底误判：标题同时命中 bot 墙与 wall 关键词，需调整检测顺序 |
| agent 标签不回收 | 卡在手递手中（pendingHandoff 豁免）；或 `cleanupIdleAgentTabs` 未周期性调度 |
| 授权后仍反复弹确认 | `userTabGrants` 是内存态且按 owner（会话）隔离：换会话/重启即失效（预期） |

## 六、已知边界（刻意为之）

- **翻牌标签保留 owner**：用户翻牌/激活后仍按 agent 标签对待（写它不需要授权），不重新归属用户。
- **wall 检测只在初始 open 时跑**：页面内二次跳转后才出现的验证码靠 LLM 自行识别 + `ask_user` 兜底（此时无 [前往处理] 按钮，AskUserBar 仅文案）。
- **多 agent 并发**：`list_tabs` 返回全部标签（含其它 agent 的），靠 `owner` 标注区分；写操作仅 `owner==自己` 的标签免授权。
- **`open` 是 L3**：默认每次 open 都弹确认条（既有行为）；信任模式下被跳过。
